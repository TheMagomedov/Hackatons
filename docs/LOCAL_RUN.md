# Локальный запуск студии в Telegram

Этот способ запускает настоящий Telegram-бот и Mini App на вашем компьютере. Публичный HTTPS обеспечивает временный туннель. Пока нет подключения нейросети, доступны ручной профиль, свои текст и изображение, календарь и согласование. Согласованные посты с наступившим временем могут отправляться в подключённый канал: это рабочий режим, а не preview.

## Что требуется

- Python 3.11+ и зависимости `requirements.txt` в `.venv` проекта. Скрипт также распознаёт `../venv` и явный `PYTHON_EXECUTABLE`.
- Созданный через BotFather бот, его токен и числовой Telegram ID владельца.
- Локальный `.env` на основе `.env.live.example`, доступный только владельцу файла: `chmod 600 .env`.
- OpenSSH для HTTPS-туннеля на HTTP-порт Mini App, по умолчанию `127.0.0.1:8766`.

Секреты вводятся в локальный `.env`; не присылайте их в чат, не помещайте в команды или Git. Скрипт не читает `.env` как shell-код и не выводит его значения. Основные поля: `APP_MODE=live`, `OWNER_TELEGRAM_ID`, `TELEGRAM_BOT_TOKEN`, `BOT_FACTORY=app.bot.adapter:build_bot`, `MINI_APP_URL`. Полный список и фабрики находятся в шаблоне. `DATA_DIR=var/live` сохраняет рабочие материалы между перезапусками.

## Рекомендуемый временный запуск: один управляющий процесс

Из корня проекта на macOS/Linux:

```bash
scripts/run-local-tunnel.sh --check --without-ai
scripts/run-local-tunnel.sh --without-ai
```

Перед запуском остановите прежние процессы приложения и туннеля. Launcher не отключает чужие процессы и откажется запускаться, если порт уже занят. `--check` проверяет локальную конфигурацию без сети, Telegram и записи базы. Флаг `--without-ai` явно отключает модель только у дочернего приложения; без него используется существующая конфигурация.

`run-local-tunnel.py` запускает собственные SSH и Python-процессы. Он читает структурированные события [`--output json`](https://localhost.run/docs/cli), принимает адрес только из события регистрации туннеля с ожидаемым доменом, затем передаёт `MINI_APP_URL` дочернему приложению через окружение. `.env` остаётся неизменённым; содержащийся в нём старый временный URL для этого режима не используется. Ключи не передаются в аргументах команд и не выводятся в лог.

В реальном прогоне бесплатный `nokey`-туннель менял hostname даже при продолжающемся SSH-соединении. При новом адресе launcher мягко останавливает только своё приложение, ждёт завершения и запускает его с новой ссылкой. Бот обновляет кнопку меню при старте. При разрыве SSH предусмотрено повторное подключение; после остановки launcher завершает свои дочерние процессы. Поведение разбора событий, смены адреса и остановки проверено отдельно; для постоянной работы нужен стабильный HTTPS-домен.

После смены адреса закройте старое окно Mini App и откройте его через актуальную кнопку меню бота либо отправьте новый `/start`. Кнопки в старых сообщениях сохраняют старые ссылки. Перезапуск при смене адреса кратковременно прерывает приложение; выполнявшиеся операции восстанавливаются по правилам backend. Результат прерванной отправки требует проверки канала, а не слепого повтора.

Для остановки нажмите `Ctrl+C` в окне launcher. Не запускайте параллельно `run-local-live.sh`: это альтернативный способ запуска того же приложения.

## Ручной вариант: туннель и приложение в разных терминалах

Этот вариант удобен для диагностики или заранее заданного стабильного HTTPS URL. Для меняющегося бесплатного адреса используйте launcher выше.

### 1. Запустить туннель

Для временной проверки используется [localhost.run](https://localhost.run/docs/). Из корня проекта:

```bash
mkdir -p var/local-tunnel
ssh -o IdentitiesOnly=yes -o IdentityFile=/dev/null \
  -o UserKnownHostsFile=var/local-tunnel/known_hosts \
  -o StrictHostKeyChecking=accept-new \
  -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
  -o ConnectTimeout=15 \
  -R 80:127.0.0.1:8766 nokey@localhost.run
```

Команда не использует ваши SSH-ключи. Из вывода туннеля возьмите выданный HTTPS-адрес и сохраните в `.env` единственное поле:

```dotenv
MINI_APP_URL=https://выданный-хост/mini/
```

Не копируйте адрес из старого сообщения: временный hostname может измениться после перезапуска. Если меняли `MINI_APP_PORT`, замените порт в `-R`. Туннель и приложение нужны одновременно; до запуска приложения upstream может отвечать ошибкой. Не отключайте проверку ключа SSH-сервера при предупреждении об изменении сохранённого ключа.

### 2. Проверить конфигурацию и запустить приложение

Во втором терминале из корня проекта:

```bash
scripts/run-local-live.sh --check
scripts/run-local-live.sh --without-ai
```

`--check` проверяет локальные поля и зависимости без запуска бота, записи базы или сетевых запросов. Успешная проверка не подтверждает доступность токена, туннеля или Telegram.

`--without-ai` явно отключает текстовую и графическую нейросети только для этого процесса, не меняя `.env`. Без флага скрипт использует существующую конфигурацию, включая подключённые позднее провайдеры. Сам скрипт не запускает туннель, не обновляет его адрес и не устанавливает зависимости.

Для нестандартного окружения:

```bash
PYTHON_EXECUTABLE=/абсолютный/путь/к/python scripts/run-local-live.sh --without-ai
```

В логе должен появиться успешный контакт с ботом. Откройте его личный чат, отправьте `/start` и нажмите «Открыть студию». Inline-кнопка приходит сразу; `/start` также повторно устанавливает кнопку меню, если на самом первом запуске Telegram ещё не знал личный чат владельца. Рабочие данные доступны только Telegram ID, указанному владельцем.

## Проверить результат

1. Откройте выданный HTTPS-адрес с путём `/mini/health`: должен быть ответ приложения. Это проверяет HTTP-маршрут, а не права публикации.
2. Откройте Mini App через кнопку бота: профиль бизнеса, сохранение ручного черновика и повторное открытие должны работать. Обычный браузер без подписи Telegram не получает доступ к рабочей базе.
3. Для публикаций добавьте бота и владельца администраторами отдельного тестового канала. В студии подключите канал, проверьте материал, задайте будущее время и согласуйте актуальную версию.

На один токен запускайте только один polling-процесс. Приложение не отключает существующий webhook автоматически. При конфликте используйте выделенного бота или сначала разберитесь, где уже работает этот токен.

## Текущее ограничение при смене канала

Для создания черновика сейчас нужны подтверждённый профиль и подключённый канал. Пост сохраняет выбранный канал вместе со своей версией. При смене канала бизнеса прежнее согласование снимается; переназначение уже созданного поста через интерфейс пока недоступно. Для нового канала создайте новый черновик, проверьте адрес назначения и согласуйте его отдельно.

## Остановка ручного запуска и ограничения

Для остановки нажмите `Ctrl+C` сначала в терминале приложения, затем в терминале туннеля. Сохранённые данные остаются в `DATA_DIR`. При следующем запуске начните с туннеля, обновите `MINI_APP_URL`, запустите приложение и снова отправьте `/start`, чтобы получить актуальную кнопку.

При выключении компьютера, сне, обрыве сети или остановке туннеля Mini App извне недоступен. Для круглосуточной работы используйте сервер и постоянный домен по [инструкции HTTPS/Docker](MINI_APP.md). Ссылку временного туннеля не следует выдавать за постоянный адрес продукта.
