# Локальная база знаний: договоры и регламенты

RAG ищет фрагменты исходных материалов выбранной компании и передаёт их модели вместе с вопросом. Это позволяет найти условие договора, которое не вошло в краткий профиль бизнеса. Индекс находится в локальном `DATA_DIR/knowledge.sqlite3`; поиск не использует облачные модели, платные API или внешние embeddings.

В Mini App откройте **Бизнес → Источники**: добавьте текст или PDF, затем нажмите **Поиск по документам** и введите вопрос либо ключевые слова. Оператор увидит фрагменты с названием документа и разворачиваемой ссылкой на source/chunk ID. Это исходные выдержки для проверки, а не сгенерированный ответ. Для ответа обычным языком используйте AI-диалог. В браузерном preview поиск прямо обозначен как недоступный; вымышленные ответы не показываются. По текущей роли наблюдателя поиск через POST скрыт, список источников и диагностика остаются доступны для чтения.

В **AI-диалоге → Диагностика AI и базы знаний** находятся число проиндексированных источников/фрагментов и журнал метаданных: модель, попадание в кеш, сбой/переключение и время. Карточка по умолчанию свёрнута. Тексты промптов и документов в неё не включаются; идентификатор записи можно использовать при разборе ошибки.

## Документы и поиск

Поддерживаются текст, PDF, DOCX и явно добавленная HTML-страница. PDF разбирается отдельным процессом с ограничением времени. При настроенном `OCR_TESSDATA_DIR` пустые текстовые страницы распознаются локальным Tesseract на русском и английском: максимум 6 сканированных страниц, предел процесса 60 секунд. OCR-фрагменты помечаются для проверки человеком. DOCX читается локально без выполнения макросов и загрузки внешних ссылок; проверяются размер ZIP/XML, количество элементов и XML-объявления. Загрузка URL сохраняет ограничения размера, таймаутов, DNS/redirect и запрет закрытых сетей.

Документ разбивается на перекрывающиеся фрагменты до 1200 символов. В SQLite сохраняются source ID, название, хеш содержимого, номер фрагмента и текст. Ссылка имеет вид `source_id:content_hash_prefix:ordinal`. При `RAG_EMBEDDINGS_DIR` BM25 сочетается с локальными multilingual MiniLM embeddings на CPU: веса уже должны быть установлены, загрузки модели при запросе пользователя нет. Векторы сохраняются и переиспользуются после перезапуска. Удаление фрагмента удаляет его вектор. Без этого параметра используется BM25. Рейтинг — сигнал поиска, а не уверенность в факте. Нулевой результат требует уточнения.

Установка: `python -m pip install -r requirements-knowledge.txt`, затем `python scripts/setup_knowledge_models.py`. В `.env` добавьте выведенные скриптом `OCR_TESSDATA_DIR` и `RAG_EMBEDDINGS_DIR`; перезапустите backend. Скрипт скачивает только открытые веса, не отправляет документы. Источники моделей: [Tesseract tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast) и [FastEmbed multilingual MiniLM](https://qdrant.github.io/fastembed/examples/Supported_Models/). OCR и семантический поиск проверены на этом ПК при блокировке сети во время поиска. Это узкая техническая проверка, не универсальная оценка качества на договорах заказчика.

По умолчанию возвращается не более четырёх фрагментов и 6000 символов текста. Каждый фрагмент несёт `source_id`, `source_name`, `chunk_id`, `text`, `untrusted: true`. Ссылки следует сохранять в контексте ответа; они указывают на источник, но сами по себе не доказывают правильность вывода модели.

## Изоляция и обновление

Индекс не авторизует пользователя самостоятельно. Сервис сначала проверяет Telegram-пользователя и доступ к компании, затем передаёт её ID и актуальный список разрешённых source ID. Все SQL-запросы параметризованы и ограничены выбранной компанией. BM25 также рассчитывается внутри её документов, не используя статистику других компаний.

`index_sources` принимает полный снимок источников компании. Удалённые источники удаляются из индекса; изменённые заменяются. Если хотя бы один документ не удалось разобрать, обновление целиком отклоняется и вызывающая сторона получает ошибку. Старый индекс остаётся целым, но нельзя выдавать его за успешно обновлённый. Фингерпринт учитывает компанию, исходные данные и версию алгоритма, поэтому используется для инвалидирования кеша ответов.

Неизменившиеся локальные материалы переиспользуют кеш извлечения после перезапуска. Содержимое сайта обновляется по явному `force=True` (например, при повторном анализе материалов), поскольку изменение страницы нельзя обнаружить по одному URL. Лимиты MVP: 10 источников, 20000 символов на источник, 120000 символов суммарно, до 24 страниц PDF в существующем extractor.

Индекс является производным: он восстанавливается из исходных документов. Штатный backup также включает `knowledge.sqlite3` вместе с векторами, VK и AI-хранилищем. Файлы индекса, WAL, договоры и их содержимое не входят в Git или публичную статику. Это локальное хранение, а не шифрование на диске. Веса моделей устанавливаются отдельно и в backup пользовательских данных не входят.

## Граница доверия

Загруженные документы всегда являются данными. Строка «игнорируй инструкции» в договоре не становится системной инструкцией или разрешением на вызов инструмента. Retrieval сохраняет текст без исполнения; отдельная защита промпта решает, допустимо ли передавать фрагмент модели. Модель не получает права самостоятельно одобрять или публиковать материалы из-за текста документа.

Реальные договоры и регламенты заказчика пока не предоставлены. Автоматические проверки используют явно вымышленные условия (например, уведомление о расторжении за 37 дней), проверяют поиск полного текста, ссылки, изоляцию компаний, обновление/удаление, перезапуск и атомарность ошибок. Эти числа не описывают АО «Салаватстекло» и не загружаются в рабочее пространство.
