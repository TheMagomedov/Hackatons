# Роль 1: AI-модуль для принятого backend

Модуль реализует `app.shared.ports.AIProvider` из `main` без копий общих моделей.
Подключение: `AI_PROVIDER_FACTORY=app.ai.provider:build_provider`.
Фабрика синхронная; сеть начинается только при вызове async-метода.
Runtime закрывает клиент через `await provider.close()`.

## Что доступно

| Метод | Результат |
| --- | --- |
| `build_profile(list[SourceInput])` | `BusinessProfile` с фактами, ID источников, предположениями и вопросами |
| `interpret_request(text, context)` | `TaskIntent`: prepare, revise_text, revise_image, report или clarify |
| `make_plan(profile, request)` | `ContentPlan` с разными темами и ограничением числа постов из Settings |
| `write_post(profile, item)` | `TextDraft` с текстом, заданием изображения, ID источников и предупреждениями |
| `revise_text(profile, current_text, feedback)` | Новая редакция `TextDraft`; версию и согласование меняет backend |
| `extract_source(SourceInput)` | Локальный `ExtractedSource(id, text)` для обработки внутри AI-модуля |

Для `text` читается `source.text`, для `pdf` — `SourceInput.content`, для `url` —
одна публичная страница. ID и файл принадлежат backend. Модуль не обращается к БД,
не создаёт постоянные ID, не подтверждает профиль, не согласует и не публикует посты.
`selected_post_id` берётся только из контекста backend; при неоднозначной правке
возвращается уточнение. Время плана — предложение; окончательную проверку делает backend.

## Настройки реального AI

Загрузку `.env` выполняет общий bootstrap. Поддерживаются принятые в main `TEXT_*`
параметры; общие Settings и `.env.example` этим изменением не меняются.
Перед платным запуском проверьте выбранного провайдера и доступ к модели.

```dotenv
AI_PROVIDER_FACTORY=app.ai.provider:build_provider
TEXT_API_BASE=https://api.openai.com/v1
TEXT_API_KEY=
TEXT_MODEL=gpt-4.1-mini
TEXT_TIMEOUT_SECONDS=35
TEXT_MAX_RETRIES=1
```

Для генерации нужны ключ и модель. Без ключа фабрика возвращает провайдер с понятной
ошибкой при вызове генерации: меню Telegram и отчёты могут запускаться.
Сохранён принятый в main default TEXT_MODEL=gpt-4.1-mini, если переменная отсутствует.
Поддерживается HTTPS Chat Completions endpoint
с JSON mode (`response_format: json_object`) и `max_completion_tokens`.
Совместимость конкретного стороннего сервиса нужно подтвердить smoke-проверкой.
Ключ хранится в SecretStr и не выводится.
Не включайте HTTP wire logging и не коммитьте `.env`.

Для совместимости с первым этапом роли 1 также доступны
`AI_API_KEY/AI_BASE_URL/AI_MODEL`. Семейства не смешиваются: непустой TEXT_API_KEY
выбирает TEXT-настройки, иначе непустой AI_API_KEY выбирает AI-настройки.
Ключ одного семейства никогда не отправляется на адрес другого.
В AI-семействе модель задаётся явно. Некорректный HTTPS URL, timeout или лимит попыток
отклоняются при настройке; отсутствие ключа не превращается в ложный успех AI.

На один структурированный ответ выделен общий timeout; максимум запросов равен
`TEXT_MAX_RETRIES + 1` (настройка 0–2; для старого семейства — AI_MAX_RETRIES).
Исправление неверного JSON и повторы временных
ошибок используют один бюджет. Ошибки доступа, отказ модели и исчерпание попыток
возвращаются как безопасные доменные ошибки, без тела ответа сервиса.

## PDF и зависимости

HTTP-клиент и валидация используют уже закреплённые `httpx` и `pydantic`.
HTML обрабатывается стандартной библиотекой. Парсер PDF `pypdf==6.13.3`
уже закреплён командой в текущих requirements.txt:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
```

Версия 6.13.3 проверена после принятия общей интеграции. Если зависимости установлены
неполностью и pypdf отсутствует, HTML и текст работают, PDF возвращает понятную ошибку.
OCR, сканы, зашифрованные PDF и обход нескольких страниц сайта не поддерживаются.
Извлечение ограничивает размер, время и объём текста; внутренние URL и перенаправления
на непубличные IP запрещены. После DNS-проверки соединение закрепляется за проверенным IP.

## Проверка без ключей

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m app demo
```

Обычные тесты используют `httpx.MockTransport`: API и Telegram не вызываются.
PDF-проверки, которым нужен парсер, пропускаются только при неполной установке без pypdf.
Общее demo остаётся офлайн-демо backend.

## Проверка реальной модели без публикации

`app.ai.smoke.run_smoke(provider)` проверяет фиксированный сценарий:
описание кофейни → проект профиля → три темы → один черновик.
Это три операции AI, каждая может использовать ограниченные повторы и оплачивается
по правилам выбранного провайдера. Пользовательские данные в примере не используются.
Профиль остаётся неподтверждённым; Telegram, изображения и БД не подключаются.

После заполнения локального `.env` пример для PowerShell:

```powershell
@'
import asyncio
import json
from dotenv import load_dotenv
from app.config import Settings
from app.ai.provider import build_provider
from app.ai.smoke import run_smoke

async def check():
    load_dotenv(override=False)
    provider = build_provider(Settings())
    try:
        result = await run_smoke(provider)
        print(json.dumps(result, ensure_ascii=False, indent=2))
    finally:
        await provider.close()

if __name__ == "__main__":
    asyncio.run(check())
'@ | .\.venv\Scripts\python.exe -
```

Это диагностический вызов функции, не альтернативный runtime приложения.
Рабочая точка запуска остаётся `python -m app`.

## Границы проверки качества

Схемы, длина, допустимые действия и ссылки на источники проверяются кодом.
Профиль ограничен 20 фактами, 20 ограничениями (до 1000 символов каждое), tone
до 2000 символов и 6000 символами компактного JSON. Профиль вместе с черновиком
ограничен 11000 символами JSON: это оставляет место в текущем Media-промпте (16000)
для инструкций и обычной правки. Особенно длинную image-правку Media может отклонить.
Превышение требует исправленного ответа модели; данные молча не обрезаются.
В запросе модели запрещены выдуманные цены, скидки, свойства, отзывы и метрики;
неизвестное выносится в вопросы/предупреждения, конфликтующие сведения требуют уточнения.
Промпт и проверка ID не доказывают фактическую истинность каждого предложения:
перед общей демонстрацией необходим прогон выбранной модели на реальных примерах,
а профиль и финальный пост по-прежнему согласует пользователь.

Источники передаются как недоверенные данные. Текст сайта не может выдать модели
права публикации или изменить backend-состояние. Регрессионные тесты проверяют
разделение инструкций и источников, но не являются доказательством абсолютной
устойчивости любой модели к prompt injection.

Изменения других участников проверяются по [журналу интеграции](review-log.md).
