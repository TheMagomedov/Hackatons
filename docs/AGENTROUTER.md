# Тексты через AgentRouter

Тексты, ответы по документам и контент-планы используют один явно выбранный
внешний провайдер. FLUX, переводчик изображений, модерация, индекс документов,
база и кеш остаются на ПК. Ollama для этого режима не запускается и не проверяется.

Локальный `.env` (ключи не добавлять в Git):

```dotenv
AI_PROVIDER_FACTORY=app.ai.provider:build_provider
TEXT_API_BASE=https://agentrouter.org/v1
TEXT_API_KEY=
TEXT_MODEL=gpt-6.1-sol
TEXT_WIRE_API=responses
TEXT_REASONING_EFFORT=low
TEXT_TIMEOUT_SECONDS=120
TEXT_MAX_RETRIES=1
AI_CACHE_TTL_SECONDS=900
```

Ключ берётся из кабинета AgentRouter. Используется `POST /v1/responses`,
`reasoning: {"effort":"low"}`, `store:false` и JSON-ответ с последующей
проверкой схемы и правил приложения. `low` — минимальное поддерживаемое
рассуждение этой модели; `none` и `minimal` не поддерживаются:
[OpenAI: Reasoning effort](https://developers.openai.com/api/docs/guides/reasoning#reasoning-effort).
Ответы Responses извлекаются только из завершённых сообщений `output_text`;
незавершённый ответ, отказ или неожиданный вызов инструмента не считаются успехом.

Перед сетевым запросом работают фильтр входа и маскировка распознаваемых
персональных данных/секретов. Это эвристическая защита: внешний провайдер всё равно
получает очищенный текст и относящиеся к нему сведения компании. Ключ передаётся
только в Authorization выбранному HTTPS-адресу; перенаправления отключены.
Системная инструкция задаётся сервером, инструменты и публикации модель не исполняет.

Кеш разделён по компании, версии профиля, модели, адресу, протоколу и настройке
рассуждения. Метаданные выполнения сохраняются без промптов и заголовков.
Автоматической замены на Qwen, другую внешнюю модель или другой аккаунт нет.

## Проверка доступа

Проверка конфигурации и успешный старт сервера не доказывают доступность модели.
На 13.11.2026 запрос с предоставленным ключом к `/v1/responses` вернул
HTTP 401 `unauthorized_client_error` / `unauthorized client detected`.
Рабочая генерация через AgentRouter пока не подтверждена. Нужно разрешить
доступ собственного приложения в сервисе или получить от него подходящий endpoint/ключ.
Приложение сообщает об отказе провайдера и не выдаёт за результат шаблонный текст.
HTTP 401/403 не повторяются; исходный ответ сервиса и ключ не показываются пользователям.

Для разработки изолированные HTTP-тесты проверяют протокол, очистку входа,
кеш, отказ доступа и неполные ответы. Они не заменяют успешный живой запрос.
