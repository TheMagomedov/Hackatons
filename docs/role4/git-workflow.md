# Работа роли 4 с изменениями команды

Пользователь поручил отправлять завершённую работу в Git и проверять новые
изменения команды. Рабочая ветка — `codex/media-analytics`. Force push,
перезапись чужих правок и самостоятельное внедрение общих контрактов в этот
порядок не входят.

## Перед этапом и перед отправкой

1. Прочитать актуальные инструкции репозитория, проверить `git status`.
2. Выполнить `git fetch origin '+refs/heads/*:refs/remotes/origin/*' --prune`. Fetch получает все ветки, не меняя
   файлы рабочей копии и не выполняя автоматический merge.
3. Сохранить `python3 tools/role4_changes.py > .git/role4-review.json`. Отчёт перечисляет новые
   коммиты и затронутые пути во всех `origin/*`, включая изменения, которые
   позднее отменили в пределах той же проверки.
4. Прочитать новые diff и содержимое затронутых файлов через `git show`.
   Сначала проверить общие структуры, настройки, зависимости, хранение файлов
   и вызовы media/reports. Файлы в чужой ветке можно изучать без checkout.
5. Только после фактического обзора сохранить просмотренное состояние через
   `python3 tools/role4_changes.py --record-reviewed .git/role4-review.json`.
   Подтверждается именно сохранённый и прочитанный снимок. Если refs успели
   измениться, команда откажет в записи; нужно повторить просмотр дополнений.
6. Адаптировать свой модуль, запустить соответствующие тесты и проверить diff.
7. Добавить конкретные завершённые файлы, сделать коммит и отправить свою
   ветку. Проверить совпадение удалённого SHA с локальным после push.

Состояние обзора хранится локально в `.git/role4-monitor.json`, не в исходниках.
Скрипт сам не получает сеть, не сливает ветки и не исполняет новый код команды.
Пустой отчёт означает отсутствие изменений относительно записанного состояния,
а не прохождение тестов. Первый запуск показывает весь доступный снимок.

Если параллельно с обзором кто-то снова выполнил fetch, перед фиксацией
просмотренного состояния нужно повторить отчёт и прочитать дополнения.

## Что отправлять

В коммит входят код, профильные тесты и документация завершённого этапа.
Ключи, `.env`, база, `var/`, сгенерированные изображения и виртуальное
окружение не добавляются. Общие исключения уже закреплены backend в
корневом `.gitignore`.

В сообщении об этапе указываются ветка и SHA, реализованные интерфейсы,
настройки, проведённые проверки и оставшиеся ограничения. Успешный локальный
коммит не означает успешную отправку: push подтверждается отдельно.

## Регулярный обзор

В чате пользователя настроена локальная автоматизация Codex: каждые 15 минут
проверять Git и продолжать задачи роли 4 при значимых изменениях. Сам этот
репозиторий не устанавливает фоновые процессы. Для локальной проверки нужны
работающий компьютер, приложение и доступ к сети/GitHub. При отсутствии
изменений уведомления не отправляются.
