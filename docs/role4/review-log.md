1. Генерация изображений выполняется до создания post_id. Реализация переведена
   на `generate(BusinessProfile, TextDraft, feedback) -> GeneratedImage`.
2. `ReportInput` использует включительный период и текущие состояния постов,
   накопленные снимки реакций/подписчиков и предыдущие baseline. Reporter
   адаптирован к этим данным без выдуманной истории ошибок и ревизий.
3. Demo-подписчики приходят с источником `demo:<channel>`. Добавлено распознавание
   namespace и проверки разделения реальных/demo-данных и полноты покрытия.
4. Подтверждение обзора Git сохраняет именно ранее прочитанный JSON-снимок.
   Новый fetched-коммит между обзором и подтверждением не скрывается.
5. FileStore на macOS отклоняет symlink-компонент `/var` системного TMPDIR.
   Общие тесты проверены с абсолютным временным каталогом внутри workspace.
   Производственный код и защитные проверки FileStore не менялись.

Основные различия для интеграции:

| Альтернативные ветки | Принятый main и реализация роли 4 |

В `2d1744c:app/reports/summary.py` реакции группируются без source и
суммируются без разделения demo. Эта реализация не должна заменять reporter
роли 4 для main: наши сводки разделяют source и demo, а покрытие проверяется
отдельно. В bootstrap API-ключ хранится обычной строкой dataclass; переносить
такую конфигурацию без проверки repr/логирования не следует.

Для Telegram адаптировать предпросмотр через service.read_asset, правки через
service.revise_image, отчёт через service.build_report с parse_mode=None,
реакции через service.record_reactions. Историю ошибок и версии не восстанавливать
из текущего PostView. Точное редактирование предыдущих пикселей требует отдельного
изменения общего image-протокола.

Чтобы сохранить чужую ветку, наша работа отправляется в
`codex/media-analytics-integration`. Общие контракты и альтернативные ветки
при этом не перезаписываются.

Деревья merge `38297fa`/`455a357` и `54c6de8`/`5aba398` совпадают.
Ветка `codex/ai-integration` сначала указывала на уже прочитанный `a308032`,
затем получила два перечисленных коммита. Инструкций AGENTS.md не добавлено.
Изменения зависимостей main установлены в `.venv`: в том числе aiogram/pypdf
и закреплённый командой Pydantic 2.13.5. Сами зависимости роль 4 не меняла.

Предыдущий PR №3 включён командой в main через PR №5. Поэтому замечание выше
о несовместимости старых веток относится к их исходным SHA: текущий `main`
уже содержит перенос Telegram/AI на принятые контракты и наши media/reports.
Временные `app/media/generator.py` и `app/reports/summary.py` удалены в
`5aba398`; висящих импортов на них в итоговом дереве нет.

Учтено в текущем этапе:

- `PostStatus.EDITING` требует подписи reporter даже при нулевом количестве:
  список текущих статусов всегда содержит весь enum. Исправление с меткой
  «редактируются» появилось параллельно и в main; оно сохранено, добавлены
  regression-проверки пустого отчёта и фактического редактирования.
- Интеграционный тест удерживает настоящий demo image provider на событии.
  Пока генератор ожидает, пост имеет `editing`, прежнее согласование снято,
  наступившее расписание не публикует старую картинку и reporter доступен.
  После завершения используются возвращённые revision/asset, требуется
  новое согласование. Номер ревизии не вычисляется как `старый + 1`.
- Live Settings теперь требует явного owner_id; принятые в main значения
  тестовых fixtures сохранены. В общие Settings, storage и backend правки
  роли 4 не добавлены.
- В принятой runtime-обёртке был автоматический выбор `gpt-image-1`.
  Пользователь ещё не выбрал провайдера/модель, поэтому убран этот default:
  нужны оба непустых `IMAGE_API_KEY` и `IMAGE_MODEL`. Меню/отчёты доступны
  без них, генерация возвращает безопасную ошибку настройки без запроса.
  Demo вообще не читает live-окружение. Проверены отсутствие/пустота значений,
  отсутствие создания адаптера до настройки и передача явных значений.

Проверка полной сборки на Python 3.12: **292 passed, 205 subtests passed**,
общий Ruff и diff --check без замечаний, `python -m app demo` успешно,
внешних запросов 0. Реальные Telegram-публикации и платная генерация не запускались.

Замечания для следующей интеграции, без подмены реализации соседних ролей:

- Новая `codex/ai-integration` использует `AI_API_KEY/AI_MODEL/AI_BASE_URL` и
  требует их при bootstrap; принятый main использует `TEXT_*` и допускает
  запуск меню без ключа. Нужно согласовать конфигурацию и адаптировать
  существующий `tests/test_adapters.py`, чей конструктор ModelAI отличается.
- Новая AI-ветка ограничивает профиль/промпт в соответствии с лимитами media.
  В main этих ограничений пока нет: shared-валидный большой профиль может
  получить понятный отказ media до сетевого запроса. Увеличивать лимиты
  вслепую не следует; границы нужно учитывать при построении профиля.
- В новой AI-ветке запросы количества словами «шесть»/«десять» не распознаются
  проверкой лимита так же, как цифра 6. Это требует уточнения у роли 1.
- В Telegram `FAILED` всё ещё подписан «ошибка отправки», хотя теперь это
  также ошибка AI-правки; предпросмотр/список не показывают `post.is_demo`.
  Роли 3 нужны нейтральная подпись и явная отметка demo. Backend при этом
  сохраняет запрет согласования demo в live и блокировку старых ревизий.
