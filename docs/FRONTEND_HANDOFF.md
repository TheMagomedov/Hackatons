# Передача Mini App следующему разработчику

Текущий этап — готовый интерфейс контент-студии САЛАВАТСТЕКЛО. Модель подключается отдельно: интерфейс уже умеет работать с ручным профилем, своим текстом и изображением, версиями, согласованием и календарём. Не заменяйте рабочие запросы к backend имитацией AI.

Получение проекта, запуск и перенос рабочего окружения описаны в [DEVELOPER_TRANSFER.md](DEVELOPER_TRANSFER.md). В настоящем Telegram проверены вход владельца, подтверждение профиля и подключение приватного тестового канала с правом бота публиковать. Через рабочий API сохранены изображение и ручной черновик; отправка в канал пока не проверена.

## Где менять интерфейс

| Файл | Назначение |
| --- | --- |
| `app/miniapp/static/index.html` | Оболочка, навигация, SVG-иконки, Telegram SDK |
| `app/miniapp/static/app.js` | Пять разделов, формы, редактор, календарь, работа с API |
| `app/miniapp/static/brand.css` | Фирменные цвета, шрифты, логотип, темы и адаптивность |
| `app/miniapp/static/styles.css`, `overview.css`, `calendar.css` | Базовые компоненты и раскладка экранов |
| `app/miniapp/static/demo-store.js` | Изолированные демонстрационные данные браузера |
| `app/miniapp/static/transport.js` | Ограниченное ожидание HTTP без автоматического повтора изменений |
| `app/miniapp/server.py` | Контракт HTTP, загрузки файлов, авторизация и выдача статики |

Новые статические файлы нужно явно разрешить в маршруте `server.py`. Оригиналы логотипов, шрифтов и паттернов, их происхождение и правила применения описаны в [BRAND.md](BRAND.md). Не растягивайте логотип, не заменяйте его текстовым набором и не добавляйте тени.

## Два режима

**Preview:** `python -m app miniapp-preview` → `http://127.0.0.1:8765/mini/`. Ключи и Telegram не нужны. Вверху показано «ДЕМО», действия имитируются, изменения сохраняются только в этом браузере. Кнопка сброса восстанавливает примеры. Это удобный режим для работы над визуальной частью.

**Рабочий Mini App:** открывается кнопкой Telegram-бота, использует реальную SQLite-базу и файлы backend. Порядок запуска — в [LOCAL_RUN.md](LOCAL_RUN.md). Клиент передаёт `Telegram.WebApp.initData` в `X-Telegram-Init-Data`; сервер проверяет подпись, срок и владельца. Токен бота и ключи модели не должны попадать в JS, URL страницы, Git или архив проекта.

## Подключение модели

Настройте серверные адаптеры через `.env` и существующие контракты, без перестройки UI:

- `AI_PROVIDER_FACTORY` — профиль компании, интерпретация запроса, план, текст, правка текста;
- `IMAGE_PROVIDER_FACTORY` — подготовка изображения;
- `REPORT_PROVIDER_FACTORY` — текстовая часть отчёта.

Фабрики и параметры описаны в `.env.live.example`, [ROLE_HANDOFF.md](ROLE_HANDOFF.md) и [MINI_APP.md](MINI_APP.md). Ключи AI-провайдеров на текущем этапе не настроены. Провайдер должен возвращать предусмотренные типы, а ошибки — понятные сообщения, которые можно безопасно показать пользователю.

Основные запросы интерфейса: `GET /mini/api/state`, `POST /business/{id}/prepare`, `POST /business/{id}/chat`, `GET /job/{id}`, `POST /post/{id}/revise-text` и `/revise-image`. Полные маршруты — в `server.py`; типы данных — в `app/shared/models.py`.

AI создаёт или изменяет черновик. Согласование всегда относится к конкретной версии текста, изображения, канала и времени. Любая правка снимает старое согласование. Не добавляйте автоматическое нажатие «Согласовать» или повтор отправки после неопределённого результата.

## Проверка перед передачей

```bash
python -m pytest -q
python -m ruff check .
npm ci
npx playwright install chromium
python -m app miniapp-preview
```

В другом терминале: `npm run test:ui:unit`, `npm run test:ui`, `npm run test:ui:content`, `npm run test:ui:a11y`, `npm run test:ui:backend`. Последняя команда поднимает собственный тестовый backend и проверяет HTTP, SQLite и загрузку файлов без настоящих ключей.

Проверяйте телефон 320/390 px и desktop, обе темы, пустое пространство, поиск без результатов, редактор с изображением, ошибки сети и повтор загрузки, календарь, навигацию клавиатурой и сохранение после повторного открытия. Подробные результаты и границы проверки — в [VALIDATION.md](VALIDATION.md).

Для доступа другого разработчика передайте репозиторий и эту инструкцию. Текущая рабочая студия привязана к одному владельцу; копия исходников сама по себе не даёт доступ к его данным. Для независимой разработки используйте preview или отдельного тестового бота и отдельный `DATA_DIR`.
