# Прямой HTTPS на Windows без туннеля

При наличии публичного адреса Mini App можно открыть напрямую через Caddy на домашнем ПК. Телефону и жюри не нужны Tailscale или Cloudflare. Telegram по-прежнему нужен для входа; текстовая модель, FLUX и модерация работают на ПК.

```text
Telegram → HTTPS:443 публичного адреса → роутер → LAN-адрес ПК:443
                                                Caddy → 127.0.0.1:8766/mini/
```

Наружу доступны только `/mini/*`. Остальные пути возвращают 404. Caddy сохраняет префикс `/mini/`; проверку Telegram `initData` и ролей выполняет приложение. Ollama, ComfyUI, переводчик и API генерации не становятся публичными. Их отдельный доступ через Tailscale, если он уже настроен, не зависит от этого способа публикации студии.

## Подготовка

1. Проверьте, что WAN-адрес роутера действительно публичный. Для постоянной ссылки нужен статический публичный IP либо домен с актуальной DNS-записью. Закрепите LAN-адрес ПК в DHCP.
2. Проверьте существующие правила прежде, чем добавлять новые: TCP 80 и 443 должны вести только на выбранный LAN-адрес ПК. В Windows эти порты должны быть разрешены для Caddy. Не заменяйте правила другого сервиса, уже использующего эти порты.
3. Установите официальный Caddy 2.11.9 или более новый совместимый выпуск и проверьте контрольную сумму дистрибутива. Bootstrap ничего не скачивает и не меняет роутер, брандмауэр или автозапуск.
4. Скопируйте `deploy/Caddyfile.windows` в приватный файл, например `var/windows-run/Caddyfile.direct`. Каталог `var/` исключён из Git. Не добавляйте приватный Caddyfile, сертификаты и `.env` в репозиторий.

Шаблон слушает **конкретный LAN IPv4**, а не все интерфейсы. Поэтому он может сосуществовать с Tailscale Serve на отдельном адресе, если порты этого LAN-адреса свободны. HTTP-сайт объявлен явно, чтобы автоматическое перенаправление Caddy не создало слушатель на всех интерфейсах. UDP/HTTP3 не требуется.

## Локальная конфигурация

Пример значений в приватном `.env` — подставьте собственные адреса и пути:

```dotenv
MINI_APP_HOST=127.0.0.1
MINI_APP_PORT=8766
WINDOWS_PUBLIC_URL=https://<public-IP-or-domain>/mini/
CADDY_EXE_PATH=C:/tools/Caddy/caddy.exe
CADDY_CONFIG_PATH=var/windows-run/Caddyfile.direct
CADDY_PUBLIC_HOST=<public-IP-or-domain>
CADDY_BIND_ADDRESS=<PC-LAN-IPv4>
CADDY_STORAGE_PATH=C:/Users/<user>/AppData/Local/SalavatstekloStudio/caddy
```

`CADDY_PUBLIC_HOST` — только IP или домен, без схемы, порта и пути; он должен совпадать с `WINDOWS_PUBLIC_URL`. `CADDY_STORAGE_PATH` — постоянный приватный каталог вне репозитория. Bootstrap передаёт Caddy только эти три переменные шаблона и минимальное системное окружение; токен бота и ключи AI в окружение Caddy не попадают. Можно заменить переменные в приватном Caddyfile на конкретные значения и оставить три переменные пустыми.

Шаблон рассчитан на Mini App на `127.0.0.1:8766`. Если выбран другой `MINI_APP_PORT`, измените upstream в приватной копии. Административный API Caddy доступен только на `127.0.0.1:12019`; его нельзя пробрасывать наружу.

Чтобы сама студия обращалась к FLUX и модерации напрямую на этом ПК, задайте в приватном `.env`:

```dotenv
IMAGE_LOCAL_FLUX=1
IMAGE_MODEL=flux1-dev
FLUX_GATEWAY_PORT=8194
FLUX_GATEWAY_HOSTNAME=
FLUX_GATEWAY_PREFIX=
IMAGE_API_BASE=http://127.0.0.1:8194/v1
MODERATION_API_BASE=http://127.0.0.1:8194/v1
```

Существующие `IMAGE_API_KEY`, `MODERATION_API_KEY` и файл `FLUX_GATEWAY_KEY_FILE` должны содержать один и тот же приватный ключ. Он по-прежнему проверяется при каждом обращении к gateway. `IMAGE_LOCAL_FLUX=1` разрешает HTTP только для `flux1-dev` на точном loopback-адресе `127.0.0.1` и порту 1024–65535; внешний HTTP-адрес, `localhost` и другая модель отклоняются. Без флага остаётся обязательным HTTPS. При такой конфигурации и локальном Ollama запуск студии не зависит от Tailscale; отдельный приватный доступ к ComfyUI можно сохранить.

Для сертификата на IP явно задан Let's Encrypt и профиль `shortlived`. `default_sni` позволяет обслуживать клиентов, которые обращаются по IP без SNI. Проверка владения адресом использует HTTP-01 через публичный TCP 80. Первый выпуск сертификата может занять время, даже если локальные порты уже открылись.

## Запуск и проверки

Обычный `scripts/start-demo.cmd` запускает Caddy, только если в `.env` заданы **оба** пути `CADDY_EXE_PATH` и `CADDY_CONFIG_PATH`. Пустые пути сохраняют прежний сценарий запуска. Перед запуском `caddy adapt` проверяет конфигурацию без выдачи сертификата: разрешён только прокси `/mini/*` к локальному Mini App, перенаправление на его HTTPS-адрес и ответы 404.

Уже работающий Caddy переиспользуется только при точном совпадении активной конфигурации из локального admin API и наличии ожидаемых LAN-слушателей. Проверки имени процесса или номера версии недостаточно. Если порт занят или конфигурация отличается, bootstrap сообщает об этом и не останавливает, не перезагружает и не перенастраивает процесс.

```powershell
.venv\Scripts\python.exe scripts\start_windows_dependencies.py --check
```

`--check` не запускает Caddy и не запрашивает сертификат. `--dependencies-only` запускает только зависимости AI, без Caddy и Telegram runtime. Процессы запускаются скрыто; журнал Caddy находится в `var/windows-run/caddy.log`. Журнал запросов с заголовками Telegram не включён.

Готовность локального Caddy ещё не доказывает внешний доступ. С телефона на мобильном интернете, без Tailscale, проверьте:

- `https://<public-IP-or-domain>/mini/health` открывается с действительным сертификатом и возвращает `status: ok`.
- `https://<public-IP-or-domain>/system_stats` возвращает 404.
- `/mini/api/state` без подписанных данных Telegram возвращает 403 и не открывает данные пользователя.
- Новая кнопка студии из `/menu` открывает Mini App; создание поста и переключение разделов работают.

Не отключайте проверку сертификата ради успешной проверки. Только после внешней проверки используйте новый адрес на демонстрации.

Сертификат Let's Encrypt для IP действует около 160 часов. Caddy автоматически продлевает его; для этого нужны постоянное хранилище, интернет и доступность TCP 80. ПК должен оставаться включённым. Закрытие окна бота не завершает отдельно запущенный Caddy. Не удаляйте хранилище сертификатов при обновлении проекта. Смена публичного IP требует нового адреса, сертификата и обновления кнопок бота.

Технические источники: [параметры Caddy](https://caddyserver.com/docs/caddyfile/options), [привязка к интерфейсу](https://caddyserver.com/docs/caddyfile/directives/bind), [маршруты handle](https://caddyserver.com/docs/caddyfile/directives/handle).
