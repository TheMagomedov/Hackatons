# Запуск, диагностика и резервные копии

## Локальное окружение

Для demo используется `.env.example`, для настоящего Telegram-бота — `.env.live.example`. Скопируйте нужный пример в `.env`, заполните реальные значения и не добавляйте файл в Git. Значения уже заданных переменных окружения имеют приоритет над `.env`.

Для live нужны числовой `OWNER_TELEGRAM_ID`, `TELEGRAM_BOT_TOKEN`, отдельный `DATA_DIR`, четыре фабрики из `.env.live.example`, а для генерации — `AI_API_KEY` и `IMAGE_API_KEY`. Отсутствующий AI-ключ не включает подставную генерацию: меню доступно, операция генерации завершается понятной ошибкой.

Текстовый провайдер выбирает одно целое семейство: при наличии `TEXT_API_KEY` — `TEXT_*`, иначе при наличии `AI_API_KEY` — `AI_*`. Не оставляйте ключ старого семейства вместе с новыми URL/моделью: они не объединяются. В `.env.live.example` используется семейство `AI_*` с явно заданной моделью.

Ниже `python` означает Python из активированного `.venv`. Без активации используйте `.\.venv\Scripts\python.exe` на Windows или `.venv/bin/python` на Linux/macOS.

```bash
python -m app check
python -m app run
```

Остановка — Ctrl+C. Один процесс обслуживает один `DATA_DIR`; два polling-процесса с одним токеном Telegram не запускаются. `check` проверяет загрузку конфигурации/фабрик, но не проверяет сетевые права. `run --once` выполняет реальные действия, включая публикацию уже согласованного поста.

## Docker Compose

На машине с Docker и Compose подготовьте `.env` из `.env.live.example`, затем:

```bash
docker compose up --build -d
docker compose logs --tail=100 marketer
docker compose exec marketer python -m app status --data-dir /data
```

В `compose.yaml` путь переопределён на `/data`. Именованные volumes `marketer-data` и `marketer-backups` сохраняют данные и копии между пересозданиями контейнера. Не удаляйте volumes вместе с приложением. Процесс работает от непривилегированного пользователя; перезапуск контейнера настроен через `unless-stopped`.

Healthcheck выполняет чтение базы через `status`. Зелёный healthcheck не доказывает доступность AI/Telegram, работу всех фоновых циклов или отсутствие ошибок заданий. Проверяйте историю операций и выполните сквозной сценарий из [ACCEPTANCE.md](ACCEPTANCE.md).

Сборка контейнера проверяется отдельным заданием CI. Локальная среда разработки этой итерации не имела доступного Docker daemon; локальный запуск контейнера не заявляется как проверенный.

## Диагностика

```bash
python -m app status --data-dir var/live
```

Команда требует существующую базу и ничего не мигрирует. Она показывает версию схемы, привязку, счётчики, время последней активности, последние задания/AI-операции и исчерпавшие попытки уведомления. Вывод не содержит тексты бизнеса, запросы к модели, ответы или ключи.

В боте доступны «Задания», «Использование AI», история AI-операций и неудачные уведомления. Счётчик AI общий для владельца, по UTC: по умолчанию 100 логических операций за сутки и 2 одновременно. Ошибки и прерывания входят в счётчик. `AI_MAX_RETRIES=1` отдельно допускает один внутренний повтор текстового клиента; счётчик не является денежным бюджетом.

Для повторной доставки выбирайте конкретное исчерпавшее попытки уведомление. Действие не повторяет генерацию или публикацию. Для нового платного действия после ошибки отправьте новый запрос. Не меняйте ключи сохранённых операций или статусы SQLite вручную.

## Backup и проверка

Сначала остановите приложение. Backup получает ту же блокировку, поэтому работающий процесс приведёт к отказу команды.

```bash
python -m app backup --data-dir var/live --output backups/pre-demo
python -m app verify-backup --backup-dir backups/pre-demo
```

Каталог `backups/pre-demo` должен быть новым и находиться вне исходного `DATA_DIR`. Копия содержит согласованный SQLite snapshot, все зарегистрированные файлы и манифест с SHA-256. `.env`, виртуальное окружение и сторонние файлы каталога не копируются. База и файлы содержат частные материалы бизнеса; храните копию как закрытые данные. Копия не является резервной копией секретов провайдеров.

Docker:

```bash
docker compose stop marketer
docker compose run --rm marketer backup --data-dir /data --output /backups/pre-demo
docker compose run --rm marketer verify-backup --backup-dir /backups/pre-demo
docker compose up -d marketer
```

Для следующей копии выберите новое имя. Volume на том же диске не защищает от потери этого диска: проверенную копию следует дополнительно хранить отдельно. Удаление старых копий и расписание копирования автоматически не настроены.

## Restore

```bash
python -m app restore --backup-dir backups/pre-demo --data-dir var/restored
python -m app status --data-dir var/restored
```

Restore проверяет копию и создаёт только новый каталог; существующие данные не перезаписываются. Сохраняются бизнесы, источники, изображения, ревизии и привязка режима/владельца. Перед завершением восстановления:

- публикации ставятся на паузу, автоматизации выключаются;
- старые согласования снимаются новой ревизией: пост мог уже выйти после создания копии, поэтому одно возобновление публикаций его не отправит;
- pending-задания отменяются, running-задания и AI-операции становятся неудачными;
- прерванные правки становятся `failed`, отправки — `delivery_unknown`;
- pending outbox сохраняется: после запуска старое уведомление может прийти повторно.

Restore не включает workers и не вызывает провайдеров. Для переключения остановите прежний экземпляр, укажите восстановленный путь в `DATA_DIR`, проверьте `status/check`, затем запустите приложение. Перед новым согласованием проверьте канал, расписание и актуальность профиля каждого восстановленного черновика. Пропущенное время не переносится автоматически. Ранее опубликованные посты сохраняют свой статус.

В Docker восстановить можно, например, в `/data/restored-demo`:

```bash
docker compose stop marketer
docker compose run --rm marketer restore --backup-dir /backups/pre-demo --data-dir /data/restored-demo
docker compose run --rm marketer status --data-dir /data/restored-demo
```

Для рабочего переключения измените `environment.DATA_DIR` в `compose.yaml` на `/data/restored-demo` и выполните `docker compose up -d marketer`. Это использует тот же volume, не удаляя прежнюю базу. Не запускайте одновременно старый и восстановленный экземпляры с одним токеном Telegram.

## Обновление старой базы

Схема v3 мигрирует v1/v2, сохраняя прежние строки и неизменяемые ревизии. Сделайте backup до запуска новой версии. `status` можно использовать до миграции.

Если `binding` уже задан, используйте те же режим и владельца; `check` выполнит миграцию. Если непустая старая база не имеет привязки, подтвердите её назначение и выполните:

```bash
python -m app adopt-data --data-dir var/live --mode live --owner-id 123456
python -m app status --data-dir var/live
```

Замените ID реальным; для настоящей старой demo-базы укажите `--mode demo`. Команда не может переопределить уже записанную привязку. Старые посты без `profile_version` требуют явного просмотра по актуальному профилю и отдельного нового согласования.

Все команды `status`, `adopt-data`, `backup`, `verify-backup`, `restore` используют явно переданные пути, не читают `.env` и не вызывают провайдеров.
