# Демонстрация с Windows-ПК

Команда запускает приложение у себя. Организаторы открывают того же Telegram-бота по приглашению `reviewer` и читают исходники GitHub. `.env`, токены, приглашения, база, пользовательские файлы, журналы и авторизация Codex остаются на компьютере владельца.

## Подготовка

1. Установите Python 3.11+, Git и Windows OpenSSH Client. Создайте `.venv` и установите `requirements-dev.txt` (для эксплуатации достаточно `requirements.txt`).
2. Скопируйте `.env.live.example` в `.env`. Укажите токен своего бота, числовой ID владельца и отдельный `DATA_DIR=var/live`. Не запускайте один токен в двух polling-процессах.
3. Для текста используйте `AI_PROVIDER_FACTORY=app.ai.chatgpt:build_provider` и официальный Codex CLI с выполненным `codex login`. Проверка и ограничения: [CHATGPT_CONNECTION.md](CHATGPT_CONNECTION.md). Используется `PROVIDER_TIMEOUT_SECONDS=300`, отдельной переменной `CHATGPT_TIMEOUT_SECONDS` нет.
4. Для изображений настройте `IMAGE_PROVIDER_FACTORY=app.media.runtime:build_provider`, `IMAGE_API_BASE`, `IMAGE_API_KEY`, `IMAGE_MODEL=flux1-dev`. Для проверки содержимого задайте `MODERATION_API_BASE` и `MODERATION_API_KEY`. Обе базы — приватный HTTPS API с `/v1`, а не адрес ComfyUI. [Gateway и его внешние зависимости](../services/flux_gateway/README.md).
5. Запустите существующие ComfyUI/FLUX, переводчик и модератор. Приватный доступ через Tailscale остаётся отдельным от публичного Mini App. Tailscale нужен серверной стороне для приватного API; жюри для входа в бот он не требуется.
6. Для новой базы выполните `python -m app init`. Для переданного снимка используйте `verify-backup`, затем `restore` в **новый** каталог. Восстановление ставит публикации на паузу, отключает автоматизации и снимает старые согласования. [Эксплуатация и backup](OPERATIONS.md).

## Запуск и остановка

После настройки зависимостей можно запустить `scripts\start-demo.cmd`: он проверит FLUX и приватный gateway и запустит бот в фоне. Дополнительные локальные пути, диагностика и ограничения описаны в [WINDOWS_STARTUP.md](WINDOWS_STARTUP.md).

Из корня проекта, после активации окружения:

```powershell
.\.venv\Scripts\python.exe -m app check
.\.venv\Scripts\python.exe scripts\run-windows.py --check
.\.venv\Scripts\python.exe scripts\run-windows.py
```

Launcher создаёт временный HTTPS-туннель localhost.run только к `127.0.0.1:8766`, поднимает приложение и обновляет адрес Mini App. ComfyUI, модератор и приватные API этим туннелем не публикуются. В API Mini App проверяется подписанная Telegram-сессия и роль пользователя. Открытие обычной ссылки в браузере не даёт доступа к рабочим данным.

Оставьте процесс работающим или запускайте его скрыто через PowerShell `Start-Process -WindowStyle Hidden`, сохраняя stdout/stderr в `var/`. Корректная остановка из другого терминала:

```powershell
.\.venv\Scripts\python.exe scripts\run-windows.py --stop
```

Не закрывайте компьютер во время отправки. При неоднозначной доставке приложение ставит `delivery_unknown` и не отправляет повторно автоматически. При конфликте polling launcher останавливает свою копию. Адрес туннеля может смениться; после перезапуска открывайте свежую кнопку через `/start` или `/menu`. Это запуск для демонстрации, без гарантии постоянного адреса и круглосуточной доступности.

## Команда и жюри

Создайте отдельную личную ссылку для оператора и ограниченную ссылку для организаторов:

```powershell
.\.venv\Scripts\python.exe -m app.access --data-dir var/live create-invite --role operator --max-uses 1 --hours 168 --bot-username YourBot
.\.venv\Scripts\python.exe -m app.access --data-dir var/live create-invite --role reviewer --max-uses 10 --hours 168 --bot-username YourBot
```

Ссылки передавайте адресатам лично. Участник нажимает Start, затем «Открыть студию». Жюри видит профиль, материалы, посты, изображения, историю, календарь и отчёты. Создание, генерация, редактирование, согласование и настройки доступны владельцу/оператору. Отзыв и поведение уведомлений описаны в [TEAM_ACCESS.md](TEAM_ACCESS.md).

## Перед показом

Проверьте настоящий Telegram WebView на телефоне, подготовьте материалы двух компаний и отдельный тестовый канал. Сгенерируйте черновик, проверьте факты и изображение, задайте будущее время и согласуйте именно эту версию. Только фактическое сообщение в канале и сохранённый результат подтверждают публикацию. План показа: [DEMO_SCRIPT.md](DEMO_SCRIPT.md).

Модерация применяется к запросам, результатам AI, ручному тексту/изображению и повторно перед отправкой. Отказ модели может быть ошибочным; фильтр не гарантирует обнаружения всех нежелательных материалов. Если проверка недоступна, материал не публикуется. Брендовый шаблон применяется только к компании САЛАВАТСТЕКЛО; другим компаниям чужой логотип не добавляется.

## Перед отправкой в GitHub

```powershell
git status --short
git diff --cached --name-only
git check-ignore .env var/live/backend.sqlite3
```

Добавляйте только исходники, обезличенные примеры, тесты и документацию. Не добавляйте ZIP частной передачи, `.env`, API-ключи, ссылки приглашений, `var/`, `backups/`, веса моделей или каталог авторизации Codex. Для переноса рабочей установки используйте отдельный защищённый канал передачи, затем штатное восстановление.
