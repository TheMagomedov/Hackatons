# Доступ команды и организаторов

Это одно общее пространство демонстрации. Его исходный владелец остаётся в `runtime_binding` и `Business.owner_id`; приглашённые пользователи не подменяются его Telegram ID. Отдельные организации и независимые арендаторы здесь не реализованы.

Роли:

| Роль | Возможности |
| --- | --- |
| Владелец | Постоянный доступ к собственному пространству; локальное управление приглашениями |
| `operator` | Подготовка, правка, согласование, настройки канала и публикаций в общем пространстве |
| `reviewer` | Просмотр профиля, постов с изображениями, истории, заданий и отчёта; без генерации, изменения и публикации |

В боте и Mini App нужен проверенный Telegram ID. Неприглашённый пользователь получает отказ. Скрытые кнопки не служат защитой: сервис отклоняет вызовы изменений от наблюдателей, даже если они вручную сформировали запрос или callback. Платные AI-действия недоступны наблюдателю. Контекст ввода бота (`pending`, выбранная компания, текущий запрос) отдельный для каждого участника.

## Приглашение

Команды запускает доверенный локальный администратор на компьютере backend. Они читают указанную SQLite, не загружают `.env`, провайдеры и не обращаются к Telegram. Перед обновлением работающей установки штатно остановите backend и сделайте резервную копию: схема 5 добавляет таблицы доступа, не меняя владельца и старые материалы.

```powershell
python -m app.access --data-dir "C:\path\to\data" create-invite --role reviewer --max-uses 5 --hours 168 --bot-username YourBot
python -m app.access --data-dir "C:\path\to\data" create-invite --role operator --max-uses 1 --hours 24 --bot-username YourBot
```

Вывод содержит личную ссылку `https://t.me/YourBot?start=join_…`. Пользователь открывает её и нажимает Start. Telegram ID заранее не требуется. Ссылка оператора даёт право изменять и согласовывать публикации: передавайте её только своему участнику команды. Для организаторов используйте `reviewer`.

При запуске после смены HTTPS-адреса бот обновляет кнопку меню у владельца и всех действующих участников. `/menu`, `/start`, `/cancel` и кнопка «Главное меню» также обновляют персональную кнопку. Ссылка внутри ранее отправленного сообщения Telegram остаётся прежней: если такая кнопка перестала открываться, отправьте `/menu` и используйте свежую кнопку студии.

Токен показывается только при создании. В SQLite хранится SHA-256, без исходного токена; журнал содержит только ID приглашения/участника и роль. Не кладите личные ссылки, `.env`, базу, журналы или файлы авторизации в GitHub. Срок приглашения — до 30 дней, лимит — до 100 разных участников. Повторное открытие тем же участником не расходует ещё одно использование.

## Отзыв

```powershell
python -m app.access --data-dir "C:\path\to\data" list
python -m app.access --data-dir "C:\path\to\data" revoke-member --actor-id 123456789
python -m app.access --data-dir "C:\path\to\data" revoke-invite --invite-id INVITE_UUID
```

`list` не восстанавливает токены. Отзыв приглашения запрещает новые входы по ссылке; уже вступившего участника отзывайте отдельно через `revoke-member`. Изменение прав проверяется на каждом запросе и сохраняется после перезапуска. Старое приглашение не восстановит отозванного участника: администратор должен создать новое после отзыва. Ссылка наблюдателя не понижает действующего оператора.

Согласование хранит настоящий `approved_by`; аудит изменений содержит настоящий `actor_id`. Согласование отозванного оператора не отправляется: права повторно проверяются при выборе публикации и после проверки содержимого непосредственно перед отправкой. Даже новое приглашение оператору не восстанавливает старое согласование — нужна новая явная проверка поста. Уже начатый внешний запрос Telegram отменить гарантированно нельзя; такой результат проверяют по штатным статусам доставки.

Обычные уведомления backend остаются адресованы исходному владельцу пространства. Участники открывают актуальное состояние через бот/Mini App; приглашение не создаёт массовую рассылку.
