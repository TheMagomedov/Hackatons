# Подключение существующего аккаунта ChatGPT

В проекте есть два **явно разных** текстовых провайдера. Их выбирает настройка `AI_PROVIDER_FACTORY`:

| Режим | Значение | Авторизация |
| --- | --- | --- |
| API | `app.ai.provider:build_provider` | `AI_API_KEY` или `TEXT_API_KEY` |
| Аккаунт ChatGPT | `app.ai.chatgpt:build_provider` | Вход в официальный Codex CLI через ChatGPT |

Второй режим использует Codex CLI, а не веб-интерфейс ChatGPT. Он не переносит историю из ChatGPT, пользовательские GPT или все функции подписки. История компаний хранится в SQLite приложения. Изображения в обоих режимах создаёт отдельный `IMAGE_PROVIDER_FACTORY`; для текущего live-провайдера нужен `IMAGE_API_KEY`. Автоматической подмены ChatGPT авторизации API-ключом нет.

## Что действительно проверено

13 ноября 2026 года на машине разработки: Codex CLI **0.160.0**, `codex login status` подтвердил ChatGPT. Выполнены реальный нейтральный запрос и три вызова через новый адаптер: вымышленное описание кофейни → профиль «Тёплое зерно» → три темы → текст поста. Ответы прошли схемы и проверки фактов `ModelAI`. Публикаций и генерации изображений в этой проверке не было.

Это доказательство работоспособности текстового пути на проверенном аккаунте, а не гарантия доступности на другом аккаунте или сервере. Возможности и лимиты зависят от подписки и настроек рабочего пространства.

## Локальное подключение

Адаптер ChatGPT поддерживает Linux/macOS. На Windows используйте WSL2/Linux-контейнер или обычный API-провайдер: отдельный процесс CLI на Windows намеренно не запускается, чтобы не оставлять дочернюю генерацию после отмены.

Установите официальный CLI, затем выполните вход от того системного пользователя, который запускает backend:

```bash
npm install -g @openai/codex@0.160.0
codex login
codex login status
```

В `.env`:

```dotenv
AI_PROVIDER_FACTORY=app.ai.chatgpt:build_provider
PROVIDER_TIMEOUT_SECONDS=120
```

Остальные live-настройки Telegram и изображения сохраняются. Затем `python -m app check`, `python -m app run`. Подключайте материалы и компании через интерфейс. Backend никогда не передаёт CLI полномочия согласования или публикации.

## Сервер в Docker

Опциональный Dockerfile закрепляет ту же версию CLI. Подготовьте `.env.live.example` и выполните:

```bash
docker compose -f compose.yaml -f compose.chatgpt.yaml build
docker compose -f compose.yaml -f compose.chatgpt.yaml run --rm --entrypoint codex marketer login --device-auth
docker compose -f compose.yaml -f compose.chatgpt.yaml run --rm --entrypoint codex marketer login status
docker compose -f compose.yaml -f compose.chatgpt.yaml up -d
```

Для HTTPS Mini App добавьте `-f compose.https.yaml` к команде запуска и настройте домен по [руководству Mini App](MINI_APP.md). Авторизация хранится в отдельном volume `chatgpt-auth`; это секрет, его нельзя помещать в Git или передавать вместе с демонстрационной базой. Docker-образ собран локально: Codex 0.160.0 запускается, офлайн-демо проходит с отключённой сетью. Авторизация ChatGPT внутри серверного контейнера, HTTPS и реальная Telegram-публикация требуют доступов команды и отдельного прогона.

## Ограничения и поведение при ошибке

Адаптер проверяет способ входа перед каждым запросом. Запускает CLI без пользовательского `config.toml`, с `--ephemeral`, read-only sandbox, нулевым лимитом project instructions и отключёнными shell, приложениями, плагинами, браузером, computer use, субагентами, памятью, чтением изображений, обнаружением навыков и hooks. Это не отдельная виртуальная машина и не обещание полной изоляции домашнего каталога: режим предназначен для доверенного оператора, не публичного сервиса произвольного выполнения задач. На сервере используйте отдельного системного пользователя; Docker-вариант создаёт такого пользователя и отдельное хранилище входа.

Текст подаётся через stdin, вывод проверяется схемой и ограничениями источников; временные файлы удаляются. Ошибка входа, тайм-аут или неверный результат останавливают операцию без скрытого API fallback и автоматической повторной генерации. Отмена останавливает локальный CLI, но уже обработанный удалённый запрос мог израсходовать лимит. Дневные квоты backend продолжают действовать.

Официальные источники: [способы авторизации](https://learn.chatgpt.com/docs/auth), [неинтерактивный запуск и JSON Schema](https://learn.chatgpt.com/docs/non-interactive-mode). Проверено 13.11.2026.
