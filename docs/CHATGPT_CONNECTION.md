# Подключение существующего аккаунта ChatGPT

Облачные текстовые провайдеры выбираются явно. Их выбирает настройка `AI_PROVIDER_FACTORY`:

| Режим | Значение | Авторизация |
| --- | --- | --- |
| API | `app.ai.provider:build_provider` | `AI_API_KEY` или `TEXT_API_KEY` |
| AgentRouter CLI | `app.ai.agentrouter:build_provider` | Только ключ AgentRouter; [настройка](AGENTROUTER.md) |
| Аккаунт ChatGPT | `app.ai.chatgpt:build_provider` | Вход в официальный Codex CLI через ChatGPT |

Режим аккаунта ChatGPT использует Codex CLI, а не веб-интерфейс ChatGPT. Он не переносит историю из ChatGPT, пользовательские GPT или все функции подписки. История компаний хранится в SQLite приложения. Изображения во всех режимах создаёт отдельный `IMAGE_PROVIDER_FACTORY`; для текущего live-провайдера нужен `IMAGE_API_KEY`. Автоматической подмены ChatGPT авторизации API-ключом нет.

## Что действительно проверено

Исходная проверка разработчика от 13 ноября 2026 года: Codex CLI **0.160.0**, вход через ChatGPT; вымышленное описание кофейни → профиль «Тёплое зерно» → три темы → текст поста. Ответы прошли схемы и проверки фактов `ModelAI`. Публикаций и генерации изображений в этой проверке не было.

Дополнительная проверка на текущем Windows-ПК: нативный `codex.exe` **0.167.0-alpha.4.1** из установленного Codex desktop, существующий вход `Logged in using ChatGPT`. Офлайн-тесты проверили передачу русского текста через stdin, удаление API/Telegram-ключей из окружения, отказ до запуска при ошибке назначения Windows Job Object, остановку дерева при отмене/тайм-ауте/закрытии и очистку оставшегося дочернего процесса. Авторизация не переносилась и не изменялась.

Реальный Windows smoke прошёл через этот адаптер на вымышленном магазине «Липовый свет»: профиль (11,19 с) → план одного поста (13,80 с) → пост (9,52 с) → ответ с учётом истории (9,14 с). Схемы и проверки источников прошли; получены два факта с source_id, один пост на 250 символов и ответ о кружках из контекста компании. После завершения у клиента не осталось процессов или jobs. Бот, публикация и генерация изображений в этот тест не входили. Идентификатор фактической модели не сохранялся; версия CLI не равна версии модели.

Это доказательство работоспособности текстового пути на проверенном аккаунте, а не гарантия доступности на другом аккаунте или сервере. Возможности и лимиты зависят от подписки и настроек рабочего пространства.

## Локальное подключение

Адаптер ChatGPT поддерживает Windows, Linux и macOS. На Windows выбирается только нативный `codex.exe` из `PATH`: `.cmd`/`.ps1`-обёртки не запускаются. Windows runner ожидает разрешающий байт stdin; backend сначала назначает его в Job Object с `KILL_ON_JOB_CLOSE`, затем разрешает запуск CLI. Отмена, тайм-аут, закрытие backend и обычное завершение закрывают job вместе с потомками. Ошибка назначения останавливает runner до запуска CLI. На Linux/macOS используется отдельная группа процессов.

Если Codex desktop уже установлен и выполнен вход через ChatGPT, проверьте из того же окружения, где запускается backend:

```powershell
Get-Command codex.exe
codex.exe --version
codex.exe login status
```

Если нативный исполняемый файл не находится, добавьте его каталог в `PATH` запуска backend. Повторный вход при существующем `Logged in using ChatGPT` не нужен. Содержимое файлов авторизации нельзя копировать в проект или `.env`. WSL хранит авторизацию отдельно; Windows-режим позволяет использовать уже выполненный вход без настройки WSL.

На Linux/macOS установите официальный CLI, затем выполните вход от того системного пользователя, который запускает backend:

```bash
npm install -g @openai/codex@0.160.0
codex login
codex login status
```

В `.env`:

```dotenv
AI_PROVIDER_FACTORY=app.ai.chatgpt:build_provider
PROVIDER_TIMEOUT_SECONDS=120
```

Остальные live-настройки Telegram и изображения сохраняются. Затем `python -m app check`, `python -m app run`. Подключайте материалы и компании через интерфейс. Backend никогда не передаёт CLI полномочия согласования или публикации.

## Сервер в Docker

Опциональный Dockerfile закрепляет ту же версию CLI. Подготовьте `.env.live.example` и выполните:

```bash
docker compose -f compose.yaml -f compose.chatgpt.yaml build
docker compose -f compose.yaml -f compose.chatgpt.yaml run --rm --entrypoint codex marketer login --device-auth
docker compose -f compose.yaml -f compose.chatgpt.yaml run --rm --entrypoint codex marketer login status
docker compose -f compose.yaml -f compose.chatgpt.yaml up -d
```

Для HTTPS Mini App добавьте `-f compose.https.yaml` к команде запуска и настройте домен по [руководству Mini App](MINI_APP.md). Авторизация хранится в отдельном volume `chatgpt-auth`; это секрет, его нельзя помещать в Git или передавать вместе с демонстрационной базой. Docker-образ собран локально: Codex 0.160.0 запускается, офлайн-демо проходит с отключённой сетью. Авторизация ChatGPT внутри серверного контейнера, HTTPS и реальная Telegram-публикация требуют доступов команды и отдельного прогона.

## Ограничения и поведение при ошибке

Адаптер проверяет способ входа перед каждым запросом. Запускает CLI из отдельного временного каталога без пользовательского `config.toml` и execpolicy rules (`--ignore-user-config`, `--ignore-rules`), с `--ephemeral`, read-only sandbox, отключённым web search, нулевым лимитом project instructions и отключёнными shell, приложениями, плагинами, браузером, computer use, субагентами, памятью, чтением изображений, обнаружением навыков и hooks. В окружение попадает только явный список системных переменных и настроек соединения; API-ключи и Telegram-токены backend не передаются. Сеть для связи самого CLI с OpenAI необходима; запрет инструментов и sandbox не означают офлайн-генерацию. Это не отдельная виртуальная машина и не обещание полной изоляции домашнего каталога: режим предназначен для доверенного оператора, не публичного сервиса произвольного выполнения задач. На сервере используйте отдельного системного пользователя; Docker-вариант создаёт такого пользователя и отдельное хранилище входа.

Текст подаётся через stdin (входные данные до 160 000 символов, полное сообщение до 700 000 байт UTF-8), вывод до 512 000 байт проверяется схемой и ограничениями источников; временные файлы удаляются. Ошибка входа, тайм-аут или неверный результат останавливают операцию без скрытого API fallback и автоматической повторной генерации. Отмена останавливает локальный CLI, но уже обработанный удалённый запрос мог израсходовать лимит. Дневные квоты backend продолжают действовать. После обновления CLI повторите тесты адаптера: имена экспериментальных feature flags могут меняться.
