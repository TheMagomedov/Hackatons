# Воспроизводимые проверки качества и защиты

Запуск без моделей, ключей, Telegram и сети:

```powershell
.venv\Scripts\python.exe -m app.evals --output var/evals/report.json
```

Команда использует только встроенные **вымышленные** примеры, отдельную временную SQLite и тестовый сервис инструментов. Она не открывает рабочую базу, не читает `.env`, не вызывает генерацию и не публикует посты. Индекс удаляется после завершения. В отчёте остаются версии компонентов, идентификаторы проверок, pass/fail и суммарные показатели; исходные тексты, реквизиты и ответы пользователей туда не записываются. Результат записывается атомарно, ограничен 200 КБ, каталог `var` исключён из Git.

Код завершения: `0` — все проверки прошли; `1` — хотя бы один сценарий выявил регрессию; `2` — сам запуск или запись отчёта не завершились. Полный `pytest` также запускает эти evals и проверяет, что намеренное отключение guard приводит к ошибкам, а не к ложному успеху.

## Что измеряется

| Группа | Размеченные сценарии |
| --- | --- |
| `known_injection` | Прямой обход инструкций на русском/английском, раскрытие системного промпта и ключа, подмена роли, публикация без согласования, zero-width, команда выгрузки секрета |
| `benign_input` | Запрос поста, инструкция по уходу, запрет публикации без согласования, вопрос по договору и обычный регламент |
| `privacy` | Маскировка искусственных email/телефона/паспорта/ключа; сохранение UUID источника, даты и структуры без изменения исходного объекта |
| `retrieval` | Поиск вымышленного пункта 7.2 за пределами краткого описания; ссылки на источник; отсутствие чужого договора и нерелевантных доказательств; лимит контекста; удаление источника |
| `tools` | Наблюдатель не создаёт задания; оператор без явного разрешения тоже; чтение ограничено компанией; подготовка создаёт только черновик; инструмента публикации нет; MCP требует инициализацию |

`fixture_pass_ratio` — доля пройденных проверок данной фиксированной группы. Это **не** полнота обнаружения всех prompt injection, не точность распознавания всех персональных данных и не показатель достоверности языковой модели. Регулярные выражения имеют пропуски и ложные срабатывания; лексический RAG может не найти перефразированный вопрос без общих слов. Обязательное согласование, проверка ролей и ограниченный каталог инструментов остаются независимыми границами защиты.

## Проверка настоящей модели

Этот набор не оценивает качество реального Qwen/FLUX. Для такой оценки нужен отдельный зафиксированный корпус разрешённых материалов компании, вопросы с размеченными правильными источниками и ожидаемыми ответами, версия модели и промпта. Следует отдельно учитывать отказ при отсутствии факта, правильность цитат, пропуски, галлюцинации, задержку и ошибки модерации. Публикация тестовых материалов требует отдельного согласования. До получения настоящих договоров вымышленные условия из evals нельзя представлять как правила Салаватстекло.
