Браузерный backend fixture не загружает `.env`, создаёт временную базу и не запускает публикационный worker. Он проверяет проводку UI/API, а не доступ к Telegram. На демонстрационных экранах есть явная маркировка режима. Согласование в UI недоступно, пока изображение не загрузилось.

Ручной API-путь проверен с `APP_MODE=live`, подписанной тестовой Telegram-сессией, настоящей SQLite и файлами, `UnconfiguredAI` и `UnconfiguredImages`: профиль → подтверждение → канал → PNG/JPEG → черновик → согласование → одна имитированная отправка. Число AI-операций остаётся 0. Дополнительно проверены дедупликация после повторного открытия базы, чужие изображения/источники, повреждённые и слишком большие картинки, устаревшие версии, изменение картинки после согласования, прошедшее время и запрет demo-файлов в live.

В этом раунде работа сосредоточена на Mini App: живых запросов к нейросетям не выполнялось. Историческая проверка аккаунта ChatGPT выше относится к предыдущему интеграционному прогону; собственная модель команды подключается отдельно. Браузерные проверки не заменяют проверку настоящего Telegram WebView и экранной клавиатуры телефона.

## Проверка фирменного оформления

Сопоставлены страницы брендбука о логотипе, цветах, шрифтах и паттернах с итоговым интерфейсом. PNG и TTF скопированы из предоставленного архива без изменения содержимого; происхождение и SHA-256 перечислены в [BRAND.md](BRAND.md). Проверены светлая/тёмная темы и пять разделов на ширинах 320, 390, 768 и 1440 px. Фактический рисунок логотипа сохраняет минимум 35 px по высоте и охранное поле X, а не только размер его прозрачного PNG-холста. Браузер подтвердил загрузку Intro Black и Avenir Next Cyr.

Preview использует `salavatsteklo.preview.v1`, не читает и не удаляет прежний `tirazh.preview.v1`. Рабочий UI не меняет ни один из этих demo-ключей. Светлая тема включается по умолчанию вне Telegram; внутри Telegram оформление учитывает цветовую схему клиента. Проверка палитры не является заявлением о полной сертификации WCAG или тестировании VoiceOver/TalkBack.

## Проверка настоящего Telegram Mini App

- Создан и настроен настоящий Telegram-бот; команда `/start` возвращает кнопку «Открыть студию».
- Кнопка открывает Mini App внутри Telegram через действующий временный HTTPS-туннель к локальному приложению.
- В авторизованной Telegram-сессии владельца создана компания и сохранён её ручной профиль.
- Запрос к рабочему API через публичный адрес без Telegram-подписи отклонён с HTTP 403.
- Нейросеть в этом запуске не подключена. Канал не подключён, отправка публикаций в настоящий канал не выполнялась.

Этот результат подтверждает вход и сохранение данных в настоящем Telegram, но не круглосуточный хостинг: приложение и временный туннель работают на компьютере. Порядок запуска и ограничения описаны в [LOCAL_RUN.md](LOCAL_RUN.md). Адрес туннеля, Telegram ID владельца и токен в документацию не включены.

## Что остаётся подтвердить с доступами команды

1. Реальную генерацию изображения выбранным провайдером и реальные права бота в тестовом канале.
2. Публикацию согласованного материала в этом канале с сохранением ссылки и уведомлением.
3. Постоянный HTTPS-домен, запуск на сервере после выключения ноутбука и серверную авторизацию ChatGPT, если выбран этот режим.
4. Живую автономную подготовку по расписанию и продолжение диалога после серверного перезапуска.

Отдельные клиентские роли, VK/MAX, мониторинг комментариев и функции конечного коммерческого продукта перечислены в [матрице ТЗ](BRIEF_COMPLIANCE.md). Успешные локальные тесты не означают, что эти функции уже реализованы.

Для воспроизведения UI-проверок: `npm ci`, `npx playwright install chromium`; preview-сервер нужен для `test:ui`, `test:ui:content` и `test:ui:a11y`. `test:ui:backend` сам запускает fixture; если Python не активирован в PATH, задайте `PYTHON_EXECUTABLE` с путём к виртуальному окружению.
