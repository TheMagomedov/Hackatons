# Проверки интегрированной версии

## Переход на локальный текст через Ollama

Добавлен `app.ai.local:build_provider`: native `/api/chat`, JSON Schema и прежние проверки ModelAI, CPU `num_gpu=0`, Qwen3 `think=false`, без прокси, redirect и облачного fallback. Целевая модель Windows-конфигурации — `qwen3:4b-instruct`; инструкция — [LOCAL_TEXT.md](LOCAL_TEXT.md). Автоматические проверки адаптера используют mock transport и не подтверждают готовность загруженных весов или качество реального ответа.

13 ноября 2026 года реальный Ollama 0.40.16 с отключённым облаком выполнил проверку `qwen3:4b-instruct` на вымышленной кофейне из `app.ai.smoke`. Использовались CPU, 16 потоков, контекст 8192, максимум 1200 выходных токенов, `max_retries=0`. После прогона `/api/ps` подтвердил `size_vram=0` для этой модели.

| Шаг | Время | Выходных токенов |
|---|---:|---:|
| Профиль | 24,94 с | 453 |
| Ответ о меню | 6,38 с | 96 |
| План из трёх тем | 26,06 с | 480 |
| Текст поста | 13,19 с | 231 |
| Сокращённая редакция | 8,99 с | 149 |

Последние четыре шага выполнены с сохранённым профилем из первого успешного вызова. Все ответы завершились с `done_reason=stop`, прошли Pydantic и прежние проверки ModelAI; профиль содержит четыре факта со `source_ids`, текст и редакция ссылаются на тестовый источник. Raw-ответы сохранены только в игнорируемом `var/local-ai-pipeline-check`, вне Git. Это прямые вызовы текстового провайдера: тест не создавал рабочие посты, не вызывал FLUX/серверную модерацию и ничего не публиковал.

В ходе диагностики обнаружены два ограничения: greedy-декодирование и неограниченный `tone` приводили к повторам до лимита токенов; первая версия плана выдумала ингредиенты, отсутствующие в источнике. Добавлены рекомендованный Qwen sampling, компактная схема с обязательными полями и явный запрет выдуманных состава/подачи/свойств. В повторном плане указанных ингредиентов нет, но остаются стилистические артефакты вроде переноса «тёплого стиля» текста на описание кофе. Последнее уточнение инструкции различает стиль ответа и свойства товара; отдельная повторная генерация после него не выполнялась. Эти результаты подтверждают работоспособность локального цикла и границы наблюдавшейся скорости, а не доказанную точность всех фактов. Проверка человеком и согласование версии обязательны; качество на настоящих материалах компании требует отдельной оценки.

Предыдущие результаты ChatGPT ниже сохранены как исторические: они относятся к облачному провайдеру. Переход на локальную генерацию не отключает сеть Telegram и явно добавленных URL-источников.

## Исправление `no tunnel`

При живой диагностике локальный `/mini/health` возвращал 200, а адрес из текущего меню Telegram — 502 `no tunnel`, несмотря на активный SSH-процесс. Структурированный ответ провайдера содержал новый адрес `*.app.lhr.life`, который прежний валидатор игнорировал. Добавлена поддержка этого точного суффикса с сохранением запрета посторонних доменов и URL-инъекций. Дополнительно включены внешний health watchdog и обновление персональных кнопок всех действующих участников.

После перезапуска: публичные страница и health — 200, API без подписи — 403, меню оператора совпадает с текущим адресом, состояние launcher — `ready`. Прошли 41 целевая проверка туннеля/health/меню и отдельная регрессия bot/access/adapters/complete_stack (42 теста); Ruff чистый. Само создание нового туннеля не выдаётся за гарантированный постоянный хостинг.

Пользователь повторно подтвердил открытие студии через новую кнопку после `/menu`. При проверке в CI обнаружена отдельная гонка создания компании: до завершения загрузки нового состояния можно было открыть форму предыдущего профиля. Переход теперь удерживает окно создания до обновления страницы и блокирует действия со старым контекстом даже после Escape. Браузерный regression-сценарий задерживает ответ `/state`, проверяет целевой бизнес формы и сохранность исходного профиля.

После следующей ротации временного адреса открытый WebView продолжал обращаться к старому origin (502), а прежний экран оставался видимым во время запроса. Навигация теперь сразу показывает выбранную вкладку и состояние загрузки; ошибка остаётся в разделе с явным повтором GET. Старые данные скрываются при смене компании, поздние ответы не заменяют новый экран. В отдельном локальном operator fixture через CUA воспроизведён 502 `no tunnel` и успешное восстановление кнопкой «Повторить загрузку». Также проверены все разделы, выбор компании, тестовая подготовка → AI-правка → время → согласование. Провайдеры fixture имитируются, публикационный worker отсутствует; новых внешних отправок не выполнялось.

Для устранения ротации добавлен режим `WINDOWS_PUBLIC_URL` с постоянным внешним HTTPS-прокси. Тесты подтверждают, что сетевой сбой не отменяет runtime, а восстановление возвращает `ready` по тому же URL. Порт 8443 разрешён только для поддомена `.ts.net`; активация Tailscale Funnel в аккаунте и реальная публичная доступность проверяются отдельно от этих тестов. Кнопки бота и студии различают AI-генерацию и ручной редактор; меню показывает компанию и следующий шаг настройки.

Для воспроизведения UI-проверок: `npm ci`, `npx playwright install chromium`; preview-сервер нужен для `test:ui`, `test:ui:content` и `test:ui:a11y`. `test:ui:backend` сам запускает fixture; если Python не активирован в PATH, задайте `PYTHON_EXECUTABLE` с путём к виртуальному окружению.
