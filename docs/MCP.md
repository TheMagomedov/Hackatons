# Инструменты AI и локальный MCP

`app.mcp_tools` предоставляет настоящий MCP-сервер через stdio и тот же проверяемый диспетчер для вызовов из приложения. Это ограниченный набор инструментов контент-студии: модель не получает произвольные команды терминала, SQL, файловую систему или доступ к URL. Подготовка создаёт задание, а worker выполняет его обычным локальным AI-пайплайном. Согласование и публикация остаются отдельными действиями человека и планировщика.

## Инструменты

| Имя | Действие |
|---|---|
| `studio_list_businesses` | Только компании, разрешённые этому подключению |
| `studio_search_knowledge` | Фрагменты документов выбранной компании со ссылками на источники |
| `studio_list_posts` | Статусы, версии и краткие выдержки постов |
| `studio_list_jobs` | Статусы и прогресс заданий |
| `studio_get_job` | Состояние конкретного задания в разрешённой компании |
| `studio_traces` | Обезличенная диагностика AI-действий |
| `studio_request_preparation` | Сохраняемое задание подготовки черновика с прежними лимитами |

Для последнего инструмента нужен явный `allow_prepare` и роль владельца/оператора. Наблюдатель видит только чтение. Инструментов `approve`, `publish`, изменения расписания или назначения ролей нет. `request_id` сохраняется при повторной попытке одного действия: существующая очередь дедуплицирует его, а повтор с другим текстом отклоняет. Черновик не превращается в публикацию из-за указания в промпте или документе.

## Запуск

Нужны уже инициализированная и привязанная база проекта, локальный `.env` и явные ID разрешённых компаний. Получите ID из вашего рабочего пространства. Команда ничего не устанавливает и не создаёт фиктивные компании.

```powershell
.venv\Scripts\python.exe -m app.mcp_tools --env-file .env --business-id <company-id>
```

Это процесс, который должен запускать **локальный MCP-клиент** и обмениваться JSON через stdin/stdout. При обычном запуске из терминала он ожидает сообщения протокола. Для нескольких компаний повторите `--business-id`. Для разрешения подготовки добавьте `--allow-prepare`. Без этого флага доступны только читающие инструменты.

Пример конфигурации клиента, поддерживающего стандартные поля `command`/`args`/`cwd`:

```json
{
  "mcpServers": {
    "studio": {
      "command": "C:/projects/Hackatons/.venv/Scripts/python.exe",
      "args": ["-m", "app.mcp_tools", "--env-file", ".env", "--business-id", "<company-id>"],
      "cwd": "C:/projects/Hackatons"
    }
  }
}
```

Пути и формат верхнего уровня зависят от клиента. Токены Telegram и AI не включаются в JSON клиента. Локальный процесс читает существующий `.env`; по умолчанию actor — настроенный владелец пространства. Для запуска от уже приглашённого участника задайте доверенную переменную `MCP_ACTOR_ID`. Права берутся из базы при **каждом** вызове, поэтому отзыв участника действует и для открытой MCP-сессии. Actor ID нельзя передать аргументом инструмента. Перечень компаний также задаёт оператор при запуске, а не модель.

Локальный stdio использует доверие к пользователю ОС, запускающему процесс. Это не OAuth и не доступ для чужих машин. Не публикуйте stdin-прокси или MCP-процесс в интернет. Для будущего сетевого MCP потребуется отдельная аутентификация; публичный HTTPS Mini App сейчас не содержит MCP endpoint.

MCP не запускает второй Telegram polling, генераторы, scheduler, публикации или восстановление незавершённых операций. Процесс открывает существующую базу, может записывать аудит и разрешённые задания через короткие транзакции SQLite. Задание ожидает штатный worker, если основной backend выключен. Производный индекс `DATA_DIR/knowledge.sqlite3` локальный, перестраивается из сохранённых источников; он не является единственной копией документов.

## Защита и границы

- Каждый вызов повторно проверяет роль и конкретную компанию; неподходящий `business_id` отклоняется до обращения к инструменту.
- Аргументы строго типизированы, неизвестные поля запрещены. Размер входного сообщения ограничен 64 КиБ; список и результаты ограничены.
- Фрагменты документов отмечаются как недоверенные данные. Они не изменяют каталог инструментов, права или правила согласования.
- На stdio-выходе применяется `redact_for_egress`: распознанные email, телефоны, реквизиты документов и секреты заменяются маркерами. UUID источников сохраняются. Это эвристический фильтр, а не гарантия удаления всех персональных данных: не подключайте конфиденциальную базу к облачному MCP-клиенту без отдельного решения о передаче данных.
- В аудите сохраняются actor, имя инструмента и идентификатор ресурса; текст запроса и документы не пишутся в записи MCP-аудита. Ошибки протокола не содержат stack trace, секретов или исходных ответов провайдера.
- stdout содержит только JSON-RPC, диагностические сообщения идут в stderr. Сервер не открывает сетевой порт.

## Протокол и проверка

Поддерживаемая версия — `2025-11-25`, transport — stdio, capability — `tools`. Реализованы `initialize`, `notifications/initialized`, `ping`, `tools/list`, `tools/call`. Задачи MCP Tasks, ресурсы, prompts, sampling и HTTP transport не заявляются. Асинхронная подготовка возвращает обычный ID задания студии; состояние можно узнать через `studio_get_job`.

`python -m pytest -q tests/tooling` проверяет реальную subprocess-сессию stdio, жизненный цикл JSON-RPC, ошибки формата, ограничения размера, маскировку, роли/отзыв, изоляцию компаний и дедупликацию задания в SQLite. Тесты не обращаются в Telegram и не публикуют материалы.

Источники протокола: [stdio transport](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), [lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle), [tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).
