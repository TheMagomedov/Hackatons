# Один запуск после перезагрузки Windows

`scripts/start-demo.cmd` запускает уже установленную локальную систему: проверяет локальный Ollama, ComfyUI, серверную защиту, переводчик и модератор; при необходимости запускает Ollama и штатный FLUX starter без браузера; затем проверяет или запускает packaged gateway и Windows-хост бота/Mini App.

Это bootstrap существующей установки. Он не устанавливает Ollama, ComfyUI, Python-пакеты, модели или Tailscale, не создаёт ключи, не меняет Serve/firewall/планировщик задач и не завершает чужие процессы. Для первого развёртывания нужны окружение проекта, установленная локальная текстовая модель, готовая FLUX-установка и сохранённый приватный Tailscale Serve path. ChatGPT и авторизация Codex для локального режима не нужны; настройка текста — [LOCAL_TEXT.md](LOCAL_TEXT.md).

## Локальная конфигурация

Для постоянного адреса Mini App используйте отдельный HTTPS-прокси к `127.0.0.1:8766` и задайте `WINDOWS_PUBLIC_URL` в приватном `.env`. Windows launcher в этом режиме не создаёт временный SSH-туннель и не перезапускает backend при сетевом обрыве. Он продолжает проверять готовность и отмечает `degraded`, пока соединение восстанавливается; уже открытое окно сможет повторить загрузку по прежнему адресу.

Вариант с Tailscale Funnel: после разрешения Funnel в аккаунте выполнить `tailscale funnel --bg --https=8443 http://127.0.0.1:8766`, затем указать `WINDOWS_PUBLIC_URL=https://<pc>.<tailnet>.ts.net:8443/mini/`. Порт 8443 должен быть свободен от других Serve-маршрутов. **Не включайте Funnel на 443, если там находятся ComfyUI и приватные API.** Для Mini App без Telegram-подписи API по-прежнему возвращает 403; внешние `/prompt`, `/system_stats` и пути FLUX на 8443 не должны существовать. Участникам Telegram Tailscale не нужен. Настройка `--bg` сохраняется сервисом Tailscale; публичную доступность и запуск после перезагрузки проверяют отдельно.

Если `WINDOWS_PUBLIC_URL` пуст, нижеописанный временный SSH-режим остаётся доступен. Выбор постоянного адреса не переносит backend с домашнего ПК: питание, интернет и работающий сервис прокси всё равно нужны.

Для HTTPS-адресов `*.ts.net` монитор на этом ПК обходит системный HTTP(S)-прокси и использует собственный маршрут Tailscale. Его статус `ready` подтверждает доступность backend и адреса с этого ПК, но не доступ из интернета: Funnel отдельно проверяют с устройства с отключённым Tailscale. Для остальных публичных адресов поведение прокси не меняется.

В приватном `.env` проекта должны быть рабочие настройки backend и дополнительные пути:

```dotenv
# Существующий launcher; также допускается полный путь к START_FLUX.cmd.
FLUX_STARTER_PATH=C:/AI/ComfyUI_windows_portable/Flux_4070Ti_Starter/start_flux.py
# Уже существующий файл ключа; значение ключа здесь не указывают.
FLUX_GATEWAY_KEY_FILE=C:/path/to/private/api_key.txt
FLUX_GATEWAY_PORT=8194
AI_PROVIDER_FACTORY=app.ai.local:build_provider
LOCAL_TEXT_MODEL=qwen3:4b-instruct
LOCAL_TEXT_API_BASE=http://127.0.0.1:11434
LOCAL_TEXT_TIMEOUT_SECONDS=300
PROVIDER_TIMEOUT_SECONDS=300
OLLAMA_EXE_PATH=C:/AI/Ollama/ollama.exe
OLLAMA_MODELS_PATH=C:/AI/Ollama/models
```

`IMAGE_API_KEY` и `MODERATION_API_KEY` должны совпадать с существующим файлом ключа, `IMAGE_MODEL=flux1-dev`. `IMAGE_API_BASE` и `MODERATION_API_BASE` должны указывать на один приватный gateway с окончанием `/v1`, например `https://<private-host>.ts.net/flux-demo-api/v1`. Hostname и prefix bootstrap получает из этого адреса; при необходимости их задают явно через `FLUX_GATEWAY_HOSTNAME` и `FLUX_GATEWAY_PREFIX`.

Ollama получает только локальный адрес из `LOCAL_TEXT_API_BASE`, выбранный каталог моделей и `OLLAMA_NO_CLOUD=1`. При повторном запуске проверяются версия сервера, `/api/status` с `cloud.disabled=true` и установленная локальная модель через `/api/show`. Сервер с включённым облаком, неподтверждённым протоколом или недоступной проверкой не используется и не перезапускается. Модель должна быть заранее установлена: bootstrap не вызывает `pull` и не выполняет генерацию при проверке готовности. Параметры не записываются в системное окружение Windows.

Только для явно выбранной облачной альтернативы `app.ai.chatgpt:build_provider` сохраняется `CODEX_CLI_PATH` к native `codex.exe`; этот режим требует входа в ChatGPT и не является локальной генерацией.

Новый packaged gateway использует отдельный порт 8194. Прежний gateway на 8193 не заменяется и не перезапускается. Штатный FLUX starter умеет самостоятельно проверить или запустить свою прежнюю службу 8193; это обычное поведение уже установленного launcher. Bootstrap не меняет его исходники.

В процессе проверки ключ не выводится в консоль, URL или аргументы командной строки. Процесс gateway получает только свои настройки; Telegram-токен backend ему не передаётся. `.env`, файлы ключей, модели и каталог `var` не входят в Git.

## Команды

Из корня проекта:

```cmd
scripts\start-demo.cmd --check
scripts\start-demo.cmd
```

`--check` выполняет проверки готовности и авторизации без запуска процессов и генерации. Для Ollama используются GET `/api/version`, GET `/api/status` и читающий метаданные POST `/api/show`; он не скачивает и не загружает модель для inference. Поэтому сразу после перезагрузки сообщение «компонент ещё не готов» ожидаемо — обычная команда запуска поднимет отсутствующие установленные зависимости.

Обычный запуск:

1. В локальном текстовом режиме проверяет Ollama с отключённым облаком. При свободном порте запускает существующий `ollama.exe serve` скрыто и проверяет наличие выбранной модели. Занятый неподтверждённый порт остаётся нетронутым.
2. Принимает занятые FLUX-порты только после проверки ожидаемого протокола и активной защиты ComfyUI. Занятый, но неподтверждённый порт приводит к отказу без захвата или перезапуска процесса.
3. При недостающих компонентах запускает существующий `start_flux.py --no-browser` и ждёт готовности.
4. Проверяет identity, readiness, обязательность авторизации и ключ локального packaged gateway; при свободном порте запускает его. Затем повторяет проверку через настроенный приватный API-адрес. Если Tailscale или Serve path недоступны, бот не запускается.
5. Запускает `scripts/run-windows.py` в скрытом процессе. Тот использует `WINDOWS_PUBLIC_URL` либо создаёт временный HTTPS-туннель и запускает бот/Mini App. Уже занятый порт Mini App не захватывается.

Прогресс запуска находится в `var/windows-run/ollama.log`, `flux-startup.log`, `flux-gateway.log`, `demo-host.log`; текущий адрес Mini App — в `state.json`. Сообщение о созданном PID не доказывает успешный polling или доступность Telegram: откройте бот, нажмите `/start` и проверьте студию. Во временном режиме URL может измениться при новом подключении туннеля.

Запуск принимает структурированные адреса `*.lhr.life`, `*.app.lhr.life` и `*.localhost.run`. Внешний `/mini/health` проверяется каждые 15 секунд: после трёх подряд неудачных проверок при здоровом локальном backend launcher переподключает свой туннель и приложение. `state.json` различает `starting`, `ready`, `degraded` и `reconnecting`; последний stderr SSH сохраняется в `tunnel.stderr.log`. Публичная проверка не передаёт ключей и не следует redirect.

После смены адреса персональные кнопки меню обновляются у всех действующих участников. URL внутри старого сообщения остаётся прежним: закройте старое окно Mini App, отправьте `/menu` и используйте новую кнопку. Переподключение пока перезапускает runtime; незавершённая AI-операция может завершиться ошибкой, а прерванная отправка — `delivery_unknown`. Автоматического повтора публикации нет.

Дополнительные режимы:

```cmd
scripts\start-demo.cmd --dependencies-only
scripts\start-demo.cmd --foreground
.venv\Scripts\python.exe scripts\run-windows.py --stop
```

Первый запускает только локальные зависимости Ollama/FLUX/gateway. Второй оставляет хост бота в текущей консоли. Последняя команда штатно останавливает бот и его туннель; общие зависимости продолжают работать. Повторный запуск всего bootstrap при уже занятом порте Mini App завершается понятным отказом, не останавливая работающую копию.

После запуска backend работает с сохранённой базой и расписаниями: ранее поставленные задания и разрешённые публикации могут продолжить выполнение по штатным правилам. ПК должен оставаться включённым, без сна и с интернетом. Автозапуск вместе с Windows и гарантия доступности 24/7 не настраиваются этим скриптом.

Проверки bootstrap покрыты тестами без настоящих внешних сервисов: чужие порты, неверный ключ, недоступный приватный адрес, порядок запуска и отсутствие секретов в окружении gateway. Полная перезагрузка Windows с повторным поднятием всех моделей требует отдельного приёмочного прогона.
