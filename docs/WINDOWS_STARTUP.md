# Один запуск после перезагрузки Windows

`scripts/start-demo.cmd` запускает уже установленную локальную систему: проверяет ComfyUI, серверную защиту, переводчик и модератор; при необходимости вызывает штатный FLUX starter без браузера; затем проверяет или запускает packaged gateway и Windows-хост бота/Mini App.

Это bootstrap существующей установки. Он не устанавливает ComfyUI, Python-пакеты, модели или Tailscale, не создаёт ключи, не меняет Serve/firewall/планировщик задач и не завершает чужие процессы. Для первого развёртывания нужны окружение проекта, готовая локальная FLUX-установка, авторизация Codex и сохранённый приватный Tailscale Serve path.

## Локальная конфигурация

В приватном `.env` проекта должны быть рабочие настройки backend и дополнительные пути:

```dotenv
# Существующий launcher; также допускается полный путь к START_FLUX.cmd.
FLUX_STARTER_PATH=C:/AI/ComfyUI_windows_portable/Flux_4070Ti_Starter/start_flux.py
# Уже существующий файл ключа; значение ключа здесь не указывают.
FLUX_GATEWAY_KEY_FILE=C:/path/to/private/api_key.txt
FLUX_GATEWAY_PORT=8194
# Необязательно, если native codex.exe уже находится в PATH обычной Windows-консоли.
CODEX_CLI_PATH=C:/path/to/native/Codex/codex.exe
```

`IMAGE_API_KEY` и `MODERATION_API_KEY` должны совпадать с существующим файлом ключа, `IMAGE_MODEL=flux1-dev`. `IMAGE_API_BASE` и `MODERATION_API_BASE` должны указывать на один приватный gateway с окончанием `/v1`, например `https://<private-host>.ts.net/flux-demo-api/v1`. Hostname и prefix bootstrap получает из этого адреса; при необходимости их задают явно через `FLUX_GATEWAY_HOSTNAME` и `FLUX_GATEWAY_PREFIX`.

Точный путь Codex можно узнать через `(Get-Command codex.exe).Source` в рабочем окружении. `CODEX_CLI_PATH` добавляет каталог только в `PATH` дочернего backend; системный и пользовательский `PATH` не меняются. `.cmd`/`.ps1`-обёртки не подходят. После обновления Codex desktop путь с номером версии пакета может измениться — обновите эту локальную настройку. Авторизация остаётся существующей, её файлы bootstrap не читает и не копирует.

Новый packaged gateway использует отдельный порт 8194. Прежний gateway на 8193 не заменяется и не перезапускается. Штатный FLUX starter умеет самостоятельно проверить или запустить свою прежнюю службу 8193; это обычное поведение уже установленного launcher. Bootstrap не меняет его исходники.

В процессе проверки ключ не выводится в консоль, URL или аргументы командной строки. Процесс gateway получает только свои настройки; Telegram-токен backend ему не передаётся. `.env`, файлы ключей, модели и каталог `var` не входят в Git.

## Команды

Из корня проекта:

```cmd
scripts\start-demo.cmd --check
scripts\start-demo.cmd
```

`--check` делает только GET-проверки готовности и авторизации. Он не запускает сервисы, генерацию или бота. Поэтому сразу после перезагрузки сообщение «компонент ещё не готов» ожидаемо — обычная команда запуска поднимет отсутствующие зависимости.

Обычный запуск:

1. Принимает занятые FLUX-порты только после проверки ожидаемого протокола и активной защиты ComfyUI. Занятый, но неподтверждённый порт приводит к отказу без захвата или перезапуска процесса.
2. При недостающих компонентах запускает существующий `start_flux.py --no-browser` и ждёт готовности.
3. Проверяет identity, readiness, обязательность авторизации и ключ локального packaged gateway; при свободном порте запускает его. Затем повторяет проверку через настроенный приватный API-адрес. Если Tailscale или Serve path недоступны, бот не запускается.
4. Запускает `scripts/run-windows.py` в скрытом процессе. Тот создаёт временный HTTPS-туннель и запускает бот/Mini App. Уже занятый порт Mini App не захватывается.

Прогресс запуска находится в `var/windows-run/flux-startup.log`, `flux-gateway.log`, `demo-host.log`; текущий адрес Mini App — в `state.json`. Сообщение о созданном PID не доказывает успешный polling или доступность Telegram: откройте бот, нажмите `/start` и проверьте студию. Текущий URL может измениться при новом подключении туннеля.

Дополнительные режимы:

```cmd
scripts\start-demo.cmd --dependencies-only
scripts\start-demo.cmd --foreground
.venv\Scripts\python.exe scripts\run-windows.py --stop
```

Первый запускает только FLUX/gateway. Второй оставляет хост бота в текущей консоли. Последняя команда штатно останавливает бот и его туннель; общие FLUX-зависимости продолжают работать. Повторный запуск всего bootstrap при уже занятом порте Mini App завершается понятным отказом, не останавливая работающую копию.

После запуска backend работает с сохранённой базой и расписаниями: ранее поставленные задания и разрешённые публикации могут продолжить выполнение по штатным правилам. ПК должен оставаться включённым, без сна и с интернетом. Автозапуск вместе с Windows и гарантия доступности 24/7 не настраиваются этим скриптом.

Проверки bootstrap покрыты тестами без настоящих внешних сервисов: чужие порты, неверный ключ, недоступный приватный адрес, порядок запуска и отсутствие секретов в окружении gateway. Полная перезагрузка Windows с повторным поднятием всех моделей требует отдельного приёмочного прогона.
