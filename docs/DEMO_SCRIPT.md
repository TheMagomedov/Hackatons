# Защита за 5–7 минут: от материалов до согласованной публикации

Цель показа: компания получает текст и изображение из своих материалов, согласовывает конкретную версию, видит реальный пост и может уточнить задачу без повторного объяснения. Второй бизнес и фоновое задание демонстрируют разделение знаний и автономность.

Это сценарий полного live-показа. Реальная отправка одной конкретной согласованной карточки уже подтверждена 13 ноября 2026 года: пользователь открыл Telegram Mini App и разрешил тестовую публикацию. Текст подготовлен отдельным настоящим AI-вызовом за 15,42 с, изображение FLUX — за 42,31 с; итоговый брендированный PNG — 1024 × 1333. Материалы загружены через ручной API-путь Mini App и согласованы под настоящим оператором: расписание 09:29:41 UTC, сохранённое состояние `published` в 09:29:44 UTC, одна попытка. ID и ссылка сохранены локально; пауза публикаций после проверки восстановлена. Частные идентификаторы и ссылка канала в репозиторий не включаются.

Это проверка заранее сгенерированных материалов → ручная загрузка → согласование → планировщик → Telegram. Единый путь «сообщение боту → генерация внутри приложения → AI-правка → публикация» в этом прогоне не проверялся; его показывает расширенный сценарий ниже. Четыре отдельных Windows ChatGPT-вызова и ранняя FLUX-генерация за 39,98 с также прошли. Постоянная работа 24/7 не подтверждена. Шаги с изменениями выполняет оператор; жюри получает режим наблюдателя.

## Отдельная офлайн-репетиция интерфейса

Запустите `python -m app miniapp-preview`. Создайте компанию, заполните профиль вручную и подтвердите его; подключите демонстрационный канал. Создайте пост со своим текстом и PNG/JPEG, сохраните без даты, затем отредактируйте текст, задайте будущее время и согласуйте. Замените изображение и покажите, что прежнее согласование снялось. Найдите пост поиском, откройте его день в календаре, перезагрузите страницу — компания и черновик сохранятся. Кнопка «Сбросить» возвращает исходное демо.

Эта репетиция показывает интерфейс и пользовательский путь; AI и отправка в preview имитируются. Полный сценарий ниже выполняется с настоящими провайдерами и тестовым Telegram-каналом. В рабочем Mini App те же ручные действия сохраняются в серверной базе и не требуют настроенной нейросети.

## До выхода к жюри

1. Выбрать один commit, выполнить `python -m ruff check .`, `python -m pytest -q`, `python -m app demo`. Записать результат. Последняя команда использует явно тестовые адаптеры, не публикует в Telegram.
2. Проверить локальный `.env`: `APP_MODE=live`, нужный `DATA_DIR`, связанный с ним `OWNER_TELEGRAM_ID`, токен и выбранные провайдеры. У существующего снимка не менять владельца ради нового участника: выдать ему приглашение `operator` по [TEAM_ACCESS.md](TEAM_ACCESS.md). Не выводить секреты на экран. Для будущей проверки публикации добавить бота и согласующего оператора администраторами **тестового** канала с нужными правами.
3. Выбрать текстовый режим явно. Для ChatGPT на Windows проверить доступность нативного `codex.exe`, `codex.exe login status` и `AI_PROVIDER_FACTORY=app.ai.chatgpt:build_provider`. Существующий вход через ChatGPT уже проверен; повторный login и копирование авторизации не нужны. Этот способ не заменяет отдельный image provider. Для API используется `app.ai.provider:build_provider`; называть этот режим подключением аккаунта ChatGPT нельзя.
4. Для Windows выполнить `python scripts/run-windows.py --check`, затем штатный запуск из [WINDOWS_DEMO.md](WINDOWS_DEMO.md). `--check` не проверяет живую генерацию. Запуск даёт текущий HTTPS-адрес `/mini/`; открывать Mini App следует из бота для подписанной Telegram-авторизации. Старую polling-копию бота заранее остановить. ПК должен оставаться включённым и подключённым к интернету. Для других способов размещения доступны `python -m app check` и `python -m app run` с настроенным HTTPS.
5. Использовать [справочник кофейни](../examples/demo-businesses/coffee.txt) и [справочник студии стекла](../examples/demo-businesses/glass-studio.txt). В интерфейсе выбрать «Описание»/«Текст» и вставить содержимое. Это вымышленные компании, а не данные заказчика хакатона.
6. Пройти весь сценарий заранее и измерить задержки AI. Для защиты подготовить запись успешного полного прогона и запасной черновик, явно обозначенный как созданный ранее. Генерация может занять больше запланированного времени; не выдавать запись или готовый материал за текущую генерацию.

## Вход организаторов в наш бот

Локальный администратор создаёт ограниченное приглашение `reviewer` по [TEAM_ACCESS.md](TEAM_ACCESS.md). Организатор открывает личную ссылку, нажимает Start и получает кнопку текущей студии. Ему доступны профиль компании, готовые посты с настоящими изображениями, история, задания и отчёт. Кнопок генерации, редактирования и согласования у него нет; вручную отправленный запрос на изменение также отклоняется.

Для проверки показать вход отдельного наблюдателя и отсутствие доступа после `revoke-member`. Приглашения и отзыв проверены автоматическими тестами; вход реальных организаторов нужно зафиксировать отдельно. Ссылку оператора не включать в публичную сдачу. Жюри видит общее пространство демонстрации, а не изолированную клиентскую организацию. Уведомления backend пока получает исходный владелец; операторы и наблюдатели проверяют результат в интерфейсе.

## Как доказать автономность

Для отдельного автономного прогона после сохранения расписания зафиксировать время первого запуска и отсутствие ожидающего задания. Закрыть Mini App/чат до наступления времени, оставив приложение на Windows-ПК работающим, без перехода ПК в сон. Затем показать время создания нового задания, его этапы и уведомление о готовности. На видео должно быть видно, что после настройки не поступало команды запустить это поручение вручную. Эту короткую запись можно показать в основном выступлении, пока обрабатывается другой запрос. Если жюри видит только `pending`, доказан запуск по расписанию; завершённую подготовку нужно показать отдельно после окончания AI-вызовов.

## Что показать про ChatGPT

Без показа токенов вывести `codex.exe --version` и `codex.exe login status`, затем указать `AI_PROVIDER_FACTORY=app.ai.chatgpt:build_provider`. На Windows 13 ноября 2026 года проверен нативный Codex CLI 0.167.0-alpha.4.1 с существующим ChatGPT-входом: профиль вымышленного магазина «Липовый свет» (11,19 с), план одного поста (13,80 с), текст 250 символов (9,52 с), ответ по истории (9,14 с). Все ответы прошли схемы и проверки источников; публикаций в этом smoke не было. Идентификатор текстовой модели не сохранялся — версия CLI не является версией модели. Отдельная реальная генерация FLUX через API заняла 39,98 с. Позднее отдельно подтверждена настоящая публикация заранее подготовленной AI-карточки через ручной API-путь, согласование и планировщик. Это не проверка всей генерации через диалог бота; длительная доступность также проверяется отдельно. Сессии CLI краткоживущие, историю компании хранит приложение.

## Пакет доказательств после репетиции

Сохранить commit, дату/время с часовым поясом, выбранные модели и текстовый режим, результат тестов, ссылку/ID реального тестового поста, версии до и после правки, время автономного задания, короткую запись перезапуска и список оставшихся ограничений. Не включать `.env`, токены, содержимое авторизации Codex и частные материалы клиентов.

При `delivery_unknown` сначала проверить канал: автоматического повтора нет. При недоступном AI показать понятную ошибку и использовать заранее отмеченную запись; не переключать генератор на demo незаметно. По окончании отключить тестовую автоподготовку, чтобы не оставлять ненужные платные задания.
