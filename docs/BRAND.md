# САЛАВАТСТЕКЛО: оформление контент-студии

Источник правил — переданный команде PDF «Брендбук от 15.11.2023г..pdf», 58 страниц. Номера ниже относятся к страницам PDF, считая обложку первой. Логотипы, паттерны и шрифты взяты из переданного архива «Основные и дополнительные визуальные элементы бренда». В репозитории находятся только выбранные файлы интерфейса; полный архив, брендбук, деловая документация и материалы с подписями не включены.

В брендбуке есть неоднозначность: на стр. 23 для тёмного цвета напечатаны RGB `0, 65, 74` и HEX `#285055`, хотя эти значения не эквивалентны. Для веб-интерфейса выбран явно напечатанный HEX `#285055`. Исходные PNG при этом не перекрашиваются. Служебные светлые/тёмные подложки являются оттенками основной палитры; контраст текста проверяется отдельно. Примеры согласований внутри брендбука описывают процессы компании и не запускают автоматическую переписку с её сотрудниками.

## Логотип и охранное поле

Оба исходных PNG имеют холст 1182×1182. Видимый рисунок занимает координаты `(178, 351)`–`(1107, 848)`, то есть примерно 929×497. Поле X равно примерно 71 исходному пикселю: `497 / 7`. Контейнер `.brand-logo-window` сохраняет область 1071×639 вокруг полного рисунка и этого поля; сам файл остаётся неизменным. Это исключает ситуацию, когда большой прозрачный холст делает логотип визуально слишком маленьким.

Для общей контент-студии выбран вариант без дескриптора конкретной производственной площадки. Минимум 110 px для блока с дескриптором со стр. 12 к этому варианту не применяется. В мобильной шапке логотип сохраняется целиком; выбор компании и смена темы переносятся на отдельную строку.

## Распределение дополнительной палитры

HEX взяты из переданных страниц брендбука. Для веб-интерфейса используются именно
HEX: отдельные подписи Pantone и RGB в исходнике расходятся. Светлые подложки
получаются смешением этих же акцентов с базовой поверхностью темы.

| Цвет | Применение |
| --- | --- |
| `#8ACCD9` | Карточка расписания, активная навигация, выбранный день, действие в главном блоке |
| `#0094A8` | AI-диалог, источники, подготовленные материалы на графике, запланированные публикации |
| `#289389` | Опубликованные материалы, завершённые шаги и задания, отправки на графике |
| `#E5917F` | Карточки согласования и незавершённые шаги настройки |
| `#DB6051` | Акценты профиля, настройки и полного отчёта; отклонённые материалы |
| `#D33835` | Ошибки и отклонение публикации; на красной кнопке белый текст |

Основные `#196C7F`, `#285055`, `#C1D0D3`, `#DDE1E1` сохраняются в главном блоке,
тексте, поверхностях и рамке интерфейса. Цвет статуса сопровождается подписью;
согласование, ошибки и отправки не различаются только цветом. График дополнительно
различает заполненные и контурные столбцы.

В тёмной теме цвета значимых столбцов и соответствующей легенды смешиваются
с белым в пропорции 75:25; фирменные голубой и зелёный оттенки и семантика
заливки/контура сохраняются. Светлая тема использует исходные цвета.
Проверка `test:ui:a11y` сравнивает фактические computed fill/stroke столбцов,
заливку/границу легенды и фон графика: не менее 3:1 в обеих темах на ширинах
320, 390, 768 и 1440 px. Это отдельная проверка значимых графических элементов
по [WCAG 2.2, SC 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html),
а не заявление о полном соответствии интерфейса WCAG.

13 ноября 2026: просмотрены светлые и тёмные мобильные/настольные снимки.
`test:ui:a11y` прошёл 40 комбинаций экрана, темы и ширины; `test:ui` и
`test:ui:content` прошли существующие пользовательские сценарии. Дополнительная
проверка фактически отрисованных цветов 462 текстовых элементов в обеих темах
не нашла нарушений порогов 4,5:1 для обычного и 3:1 для крупного текста.
Рабочий HTTPS возвращает обновлённый CSS с `Cache-Control: no-cache`.

## Что проверять при следующих изменениях

`npm run test:ui:a11y` проверяет пять экранов на 320/390/768/1440 px в двух темах, загрузку исходных логотипов, правильный цветовой вариант, высоту рисунка и охранное поле, фирменные шрифты, паттерны, контраст, доступность кнопок и клавиатурного фокуса. `npm run test:ui:unit` дополнительно проверяет сохранение паттернов в demo-хранилище и изоляцию прежнего ключа `tirazh.preview.v1`.

Preview хранится под `salavatsteklo.preview.v1` и начинается со светлой темы. В Telegram используется цветовая схема клиента. Эти интерфейсные проверки не подтверждают публикацию в реальном канале, работу нейросети или непрерывность серверного запуска; фактические результаты интеграции фиксируются отдельно в [VALIDATION.md](VALIDATION.md).
