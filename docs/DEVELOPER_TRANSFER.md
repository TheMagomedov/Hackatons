# Передача проекта разработчику

Исходники, фирменные изображения и шрифты, Mini App, бот, backend, тесты и инструкции находятся в этом репозитории. Начните с [FRONTEND_HANDOFF.md](FRONTEND_HANDOFF.md): там карта интерфейса и точки подключения модели. Репозиторий публичный; для клонирования приглашение не требуется.

## Быстро открыть интерфейс

```bash
git clone https://github.com/TheMagomedov/Hackatons.git
cd Hackatons
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m app miniapp-preview
```

Откройте `http://127.0.0.1:8765/mini/`. Это явно обозначенное демо: оно работает без Telegram и модели, хранит изменения только в браузере. Для Windows используйте `python` и `.venv\Scripts\python.exe` вместо Unix-путей.

## Получить существующего бота и данные

Текущий тестовый бот — [@SalavatContentHack2026_bot](https://t.me/SalavatContentHack2026_bot). В отдельный **приватный пакет** для владельца подготовлены `.env`, проверенный snapshot базы с изображениями и инструкция. Получите этот пакет непосредственно от владельца. В GitHub, issues, PR и публичные архивы его загружать нельзя: токен позволяет управлять ботом, а удаление коммита из текущего дерева не стирает историю.

Исходники и приватный пакет передаются отдельно. В пакете нет чужих аккаунтов, SSH-ключей и GitHub credentials. Владение ботом в BotFather остаётся у создавшего его Telegram-аккаунта; копирование токена не переводит владение и не даёт доступ к этому аккаунту.

### Перенести на новый компьютер

1. Установите зависимости по командам выше. Распакуйте приватный пакет **вне репозитория**.
2. Согласуйте остановку старого запуска с владельцем. Один токен должен обслуживаться одним polling-процессом; два компьютера одновременно не запускайте.
3. Скопируйте полученный `.env` в корень проекта. На macOS/Linux задайте `chmod 600 .env`. Не меняйте режим и ID владельца для существующей базы.
4. В командах ниже замените `/private/handoff/snapshot` реальным путём к `snapshot` из пакета. Каталог назначения `var/live` должен быть новым; restore не перезаписывает существующую базу.

```bash
.venv/bin/python -m app verify-backup --backup-dir /private/handoff/snapshot
.venv/bin/python -m app restore --backup-dir /private/handoff/snapshot --data-dir var/live
.venv/bin/python -m app status --data-dir var/live
```

5. Убедитесь, что `.env` указывает `DATA_DIR=var/live`. На macOS/Linux с OpenSSH запустите:

```bash
scripts/run-local-tunnel.sh --check --without-ai
scripts/run-local-tunnel.sh --without-ai
```

Launcher создаёт новый временный HTTPS-адрес и обновляет меню бота. Старый `MINI_APP_URL` из переданного `.env` в этом режиме заменяется в окружении процесса; вручную открывать прежнюю ссылку не нужно. Владелец отправляет боту новый `/start` и открывает студию. Для Windows используйте WSL или постоянный запуск через Docker по [MINI_APP.md](MINI_APP.md).

Restore сохраняет профиль, источники, черновики, изображения и привязку владельца. При восстановлении публикации ставятся на паузу, автоматизации отключаются, старые согласования снимаются. Не запускайте публикацию без просмотра канала, текста, изображения и будущего времени. Подробности — [OPERATIONS.md](OPERATIONS.md).

## Кто может открыть рабочую студию

MVP поддерживает одного владельца. Токен даёт разработчику возможность запустить backend, но рабочий интерфейс по-прежнему открывается только для `OWNER_TELEGRAM_ID`, которому уже принадлежит база. Простая смена этого значения не переносит существующие данные и завершится ошибкой привязки.

Для независимой разработки используйте preview или отдельный тестовый бот, собственный ID владельца и новый `DATA_DIR`. Для передачи существующих данных другому владельцу потребуется отдельная реализация миграции/ролей; сейчас её нет. Доступ на запись в GitHub выдаётся отдельно по логину разработчика.

## Что подключать дальше

- Модель команды через фабрики из [FRONTEND_HANDOFF.md](FRONTEND_HANDOFF.md); ключи AI-провайдеров пока не настроены.
- Постоянный сервер, диск и HTTPS-домен по [MINI_APP.md](MINI_APP.md). Временный запуск зависит от включённого компьютера и соединения.
- Проверку реальной публикации после согласования: тестовый канал уже подключён, черновик сохранён, но фактическая отправка в канал пока не выполнялась.

Зафиксированные проверки и границы реализации — [VALIDATION.md](VALIDATION.md). Рабочая конфигурация и snapshot не входят в публичный исходный архив.
